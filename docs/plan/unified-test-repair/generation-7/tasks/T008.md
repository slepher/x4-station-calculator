# T008：建筑规划的当前端到端行为

## Goal

在一个owner下完成建筑流、目标/Fleet、预览和显式计算/详情的必要测试重写，复用当前有效成果，补足有意义的当前行为覆盖。

## Acceptance

1. 建筑流：固定clean/seeded初态和可区别的源/目标组，菜单绑定/解绑、真实拖放、归档/恢复后精确检查目标卡片、连线和持久化身份。替换当前build-flow spec中的`count >= 0`、可有可无输出和条件通过，不能用UI没出现就跳过业务断言。
2. 目标与Fleet：保留当前有效ware目标增删改、已保存blueprint数量、方案CRUD/flow选择/Save-reload；断言持久化目标结构、数量和身份。已保存蓝图/合法目标通过fixture建立，业务变更通过UI，不能新增缺失产品能力。
3. 预览：区分用户显式目标、当前derived production与required建材；用固定游戏版本和小型可计算输入给出各自精确expected。读取previewResult可作为actual或观察，但不得用它生成自己的expected；只断言“发生变化”不足以证明正确派生。
4. 显式计算：保留小输入可手算的模块/建材/时间、修改目标后的确切结果差异、重叠产线当前去重行为、当前unplanned路径。区分preview与Compute触发时机，不借测试请求变更算法或证明全局最优。
5. 详情/steps：先追BuildPlanPanel打开modal及当前canBuildStepsScheme分支，确定固定的build-material卡片身份。用非energycells正建材目标、非空modules的当前可达输入构造正例，验证默认汇总→steps内容→切回汇总内容；另验证不满足条件的现有卡片不显示switch。禁止energycells+last、只验switch、store注入计算结果或空steps通过。
6. 旧3.3前置过时不等于steps能力不存在。定位公开正例是本任务内部工作，不再依赖旧T022 draft关卡；确证没有公开可达路径时保留已搜索入口/输入/分支和实际结果，交planner决定具体替代/退休范围。不得因单个fixture失败退休整个功能，不能自行新增入口。其余三个文件和计算有效分支继续完成。
7. 不要求四份文件全部修改；有效用例保留。所有重写/补写/合并/退休说明当前行为去向，由独立review核对oracle和可达性。
