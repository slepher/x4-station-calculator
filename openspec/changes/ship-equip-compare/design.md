# 船只建造方案对比设计
## 用户界面修订（2026-11-12，优先于下方原规划的对应描述）

- “展开对比”位于属性标题区；双侧对比时，“保留左侧／保留右侧”放在标题行内，左按钮右边缘对齐左列属性条右边缘、右按钮左边缘对齐右列属性条左边缘。选择装备期间隐藏这些操作。
- 对比复用原 ShipBuildPanelStats / MetricsPanel 的双列指标、简略／详细切换和数值＋差值条形，不新增独立视觉布局。
- B 船型选择复用 A 的原 ShipBuildSelectorView，不新增弹窗、搜索列表或独立选型界面；确认只替换 B，取消保持原会话。
- B 蓝图入口与 A 共用原浮层（包含预设、保存蓝图及原操作），仅向左弹出；选择和预设只作用于操作侧，禁止两侧使用同一保存 ID。
- 保存、另存为及退出／替换保护统一复用原 SmartSaveDialog，不保留独立的对比弹窗；双侧上下文和保存成功后才继续的行为由 presenter 管理。
- 删除可见 A/B 标记及顶部编辑对象切换；点击配装面板确定内部编辑侧。保存按钮沿用“保存”，保护对话框用左／右侧方案说明对象。
- A 侧标题保持原样；右侧标题整体按原要求水平镜像，船型／蓝图入口、入口内部控件和收藏位置反向排列，文字保持正常可读；不添加 A/B 文字标记。两侧蓝图菜单项继续左对齐，右侧浮层向左弹出。


## 现状与改造依据

- `src/components/ship-build/ShipBuildWorkspaceView.vue` 组织配装、属性、材料以及装备选择器，当前只维护一份预览蓝图。
- `ShipBuildPanelStats.vue` 的计算与展示组装位于 Vue 内，targetBlueprint 仍使用当前 selectedShip；不能直接传入异船 B 复用该假设。
- `ShipBuildPanelFit.vue` 和现有装备 presenter 依赖单例 store 的当前船／当前蓝图。实例化两份 Vue 不等于建立两份独立编辑上下文。
- `useShipBuildStore.ts` 的 blueprint、lastSavedSnapshot、forceDirty、预设标记与保存身份均围绕唯一当前蓝图。saveBlueprint/saveAsBlueprint 会更新全局 activeShipId/activeBlueprintId，并对当前对象拍快照。
- `useToolbarWorkflowController.ts`、`StationToolbar.vue` 及 `VersionSettingsModal.vue` 有保存、dirty 和活动对象读取路径，需要按使用目的区分“编辑侧保存”与“整个会话退出保护”。
- 通用 MetricsPanel/MetricItem 支持 current/target 和差值，但现有布局以目标值加差值为主，颜色按差值正负，需为对比模式明确双方数值与指标方向，保持其他调用者原有行为。
- default_maxes 按 class 提供参考刻度；ship_slots 提供按 class 统计的槽位默认最大数量。它们都不是两个方案实际值的动态最大值。

## 架构与职责

严格采用 `store → presenter → vue`。受本变更影响的船只工作台、属性面板与保存入口新逻辑通过 presenter 使用 store；不扩大为整个仓库迁移，不引入 adapter、facade、view model 等中间层。

### Store：独立方案上下文

在现有船只建造 store 内支持明确的方案上下文，复用同一套游戏数据和蓝图库；不要复制完整 Pinia store，也不要通过不断交换全局 blueprint 来渲染两侧。

每个方案上下文包含：

- 会话内稳定身份，用于异步命名／保存回调校验；与持久化蓝图 ID 分开。
- 工作蓝图、船体 ID、明确的保存目标 ID（已保存记录／未保存方案状态）。
- 独立保存基线、forceDirty、内置预设状态；同名字段的具体结构实施时遵循现有类型。
- 当前工作蓝图不与保存记录或另一侧共享可变 connections、storage 等对象。

单船时只有 A；对比时 A、B 都存在。store 保存领域工作副本及生命周期，presenter 管理编辑侧、布局和选择器展示状态。store 的领域 API 显式接受方案身份／侧参数，不猜测 UI 焦点。

建议能力边界（名称可按现有风格调整）：

- 获取指定方案船体、工作蓝图、dirty 与保存资格。
- 展开时以 A.shipId 为目标，更换 B 船型时以选定 shipId 为目标，两者共用领域选择规则：从已保存蓝图中精确匹配 shipId，排除 A 当前保存身份，按 createdAt 降序、ID 升序排序，不按 lastUpdated 或列表顺序选择，不纳入内置预设。
- 候选非空：独立载入首个候选的配装、保存目标与 clean 基线；候选为空：创建目标船型空配装、无保存目标与 clean 基线，首次保存另存为。两个业务分支显式处理，不用 sequential fallback 链掩盖状态。
- B 手动载入蓝图遵从用户选择，不被默认排序覆盖；同目标记录直接拒绝。
- 对指定方案应用连接赋值、清空配装、预设或仓储等现有编辑行为。
- 根据指定船体与蓝图计算整船领域属性；装备查询与 DLC 资格必须使用该侧上下文。
- 为指定方案构建纯预览；保存／另存为返回明确成功、取消或失败结果。
- 替换／释放方案，或将 B 提升为单船，保持工作副本与基线。

计算工具可以作为 store 内部领域计算实现，不作为 Vue 可直接调用的额外业务组装层。移出 PanelStats 中的业务计算后，presenter 只负责展示，不复制公式。

### Presenter：工作台与属性

在 ship-build/presenters 中建立工作台与属性的职责归属，并将 fit/equipment presenter 改为接收明确方案上下文。UI 状态由工作台 presenter 管理：

- mode：single / compare。
- activeSide：A / B；初始化与返回单船为 A。
- picker：closed / editingA / editingB，包含目标连接、connection/group 模式、候选与预览。
- 属性档位、蓝图选择弹窗和退出保护流程。

布局完全由状态映射产生，禁止通过 fallback 选择一个“可用蓝图”。无 B 时不得进入 editingB；数据缺失时明确停止该动作并提示。

| 模式 | Picker | 左 | 中 | 右 |
|---|---|---|---|---|
| single | closed | A 配装 | 单船属性 | 材料 |
| compare | closed | A 配装 | 属性对比 | B 配装 |
| compare | editingA | A 配装 | A 选择器 | A 装备属性对比 + 舰船修改前／后 |
| compare | editingB | B 装备属性对比 + 舰船修改前／后 | B 选择器 | B 配装 |

单船及双船 picker 均复用原 Stat 的 current/target 预览语义，presenter 提供 editingBlueprint（当前操作侧工作副本），preview 作为修改后目标。选择器打开时隐藏对比操作；关闭时重新显示 A/B 对比与退出操作。隐藏船只面板不影响 store 上下文。窄屏使用项目响应式布局，保持这三个逻辑区域的顺序。

### Vue：展示与事件

工作台根据 presenter 布局输出渲染三栏，配装面板明确接收 side。共用属性面板提供 A/B 名称、逐项双方值、B − A 差值和共同刻度；不在 Vue 内查 store 或按船只拼装指标。

“展开对比”入口放在当前蓝图名称旁，按默认选择规则初始化同 shipId 的 B；B 标题分别提供“更换船型”和“载入蓝图”。船型选择复用选择器能力但必须显式绑定 B，不得调用仅操作全局 selectedShipId 的旧路径。使用弹窗承载船型／蓝图选择，未确认前保持底层对比三栏与原 B。退出与保留 B 操作放在共用对比标题，使属性移动时仍可识别。全局工具栏提供编辑侧切换及带 A/B 的保存标签，各侧显示独立 dirty 标记。

### 右侧配装面板的镜像实现

已确认的示意以当前 `ShipBuildPanelFit.vue` 的 panel-header、arsenal-shell、left-rail、mode-tabs、group-tab-row、compatibility-box、slot-stack 和 slot-row 结构为基础。复用同一配装组件，由 presenter 根据 `mode === compare && side === B` 输出明确的镜像展示属性，不复制一套配装业务实现，不对整个面板使用 `scaleX(-1)`。

| 区域 | A／单船 | B 对比模式 |
|---|---|---|
| 头部 | 船型入口左、收藏及蓝图入口右 | 两个入口组位置互换，组内控件水平次序镜像 |
| 蓝图展开方向 | 箭头向右 | 箭头向左；相邻浮层优先向内展开并保留边界避让 |
| 装备分类竖栏 | 内容左侧 | 内容右侧；E/R/S/W/T/C/U 上下顺序不变 |
| 连接／分组与槽位标签 | 从左向右排列 | 从右向左排列，按钮文本不反转 |
| 兼容性、卡片名称 | 左对齐 | 右对齐，名称与编号不变 |
| 卡片数量 | 右侧 | 左侧 |
| 数量滑条 | 最小值左、最大值右 | 最小值右、最大值左，填充从右增长 |

布局使用显式 class、flex/grid 排列与文本对齐；仅定向调整展开箭头，不翻转文字或整组图标。仍由装备卡片本身打开选择器，不增加示意版之外的操作入口。分类的垂直排序和槽位的业务身份不因视觉排列变化而改变。

滑条需确认 `X4DualPhaseRangeSlider` 的方向能力：支持显式方向参数时复用，否则为其增加最小的可选方向支持并维持现有默认值。镜像方向必须同时作用于填充、指针位置和指针到数值的换算，保持 min/max/step、实时更新与 commit 语义；键盘与辅助技术应遵循该控件明确的方向约定，不能只翻转 CSS 后留下相反的点击行为。

镜像属性由对比角色决定，不由 activeSide 或面板屏幕坐标猜测。B 在默认及 editingB 两个状态均镜像，隐藏再显示保持一致；B 提升为单船后角色变为普通单船，立即恢复正常方向。属性对比与选择器内容保持正常阅读和原有方向。C/U 仓储子面板内部布局不在已确认镜像范围，本次仅移动其分类入口。

## 属性对比算法与展示约定

1. 分别以 A.ship/A.blueprint 与 B.ship/B.blueprint 计算领域属性。picker 打开时仅用操作侧 preview 替代该侧展示输入。
2. 根据现有指标元数据建立统一行序与简略／详细过滤，不能仅用 A 有非零值的字段过滤 B 的有效属性。货物类别分别比较，不把两船各自的不同摘要货物当作同一字段。
3. 数值显示统一单位；按字段读取双方 class 的默认上限，转换单位后取 max。槽位指标从双方 class 的 ship_slots 获取对应默认最大值；该 class 明确不存在某槽位类型视为有效零，数据表缺失视为未知。
4. 两个默认上限均存在且最大值大于零时按共同上限画条；两者均为零时无比例条；任一默认上限未知时无比例条并提示刻度不可用。实际值绝不参与上限计算。
5. 缺失实际值显示 `—`，该项差值不计算；有效零正常显示。真实值超限仍显示真实数值，绘图所有段限制在容器范围，不能让差值段越界。
6. 差值固定 B − A。字段明确 higherIsBetter、lowerIsBetter 或 neutral；颜色仅表达字段方向下的优劣，不改变数值符号。两个有效零值差值为零。

现有通用指标组件的增强应使用明确的对比呈现契约并保持其他调用者兼容，避免把船只领域规则硬编码进通用组件。

## 编辑与预览状态机

- closed → 点击某侧槽位：激活该侧，创建对应 picker，固定操作上下文。
- 候选变化：从该侧工作副本生成纯预览，复用既有 connection/group 数量分配及 shield 映射。
- 确认：应用该侧连接变更，重新计算该侧 dirty，清除预览并回到 closed。
- 取消：清除预览与 picker，工作副本不变。
- picker 打开期间，保存、另存为、编辑侧切换、替换方案、退出及保留 B 操作不可直接执行；UI 提示先确认或取消。命令入口也执行同一约束，防止快捷键绕过。
- 共用属性点击不影响 activeSide。关闭选择器后编辑侧保持原操作侧。

## 保存身份与持久化

### 全局命令路由

工具栏 presenter 将保存／另存为路由到 activeSide 的上下文。现有 workflow controller 的船只分支可以作为 presenter 内部的命令协调实现使用，但不得在 store 与 presenter 之间建立新层或将单例 blueprint 假设带入新调用。

保存弹窗打开时捕获侧和会话身份，回调前校验上下文仍一致；失效则中止，不转存另一个对象。弹窗期间阻止会话替换。普通保存、另存为与快捷键使用同一命令路径。

### 保存事务

1. 明确该侧目标是已有记录还是必须另存为的新方案；不得根据共享 activeBlueprintId 推断。
2. 准备独立持久化记录并写入现有蓝图库。另存为分配新 ID，只绑定当前侧。
3. 只有写入成功才更新该侧保存身份和基线、清除 dirty，并执行待完成退出动作。失败时保留工作副本与原基线，不能先标记为已保存。
4. 保持既有成功保存后的持久化 activeShipId/activeBlueprintId 语义，指向本次成功保存对象；此写入不得触发另一侧 reload 或重置。仅切换编辑侧不持久化身份。
5. 返回单船后，内存活动对象与保留方案一致；需写活动身份时，已有记录使用该记录身份，未保存方案明确无已保存 ID，不能把另一侧 ID 借作兜底。

不增加对比会话存储格式。刷新仍按既有活动蓝图规则加载最后保存记录，不承诺恢复两侧未保存工作副本。若实施确需修改持久化类型，必须同步对应 normalize／迁移路径；当前方案优先避免新增持久化字段。

### 禁止同蓝图与删除

以蓝图 ID 判断是否同一蓝图，与名称、船体和当前配装内容无关；A 有未保存修改不改变其身份。B 载入蓝图的候选列表禁用 A 当前蓝图并显示原因，store 提交入口再次校验；相同 ID 直接拒绝且保留原会话，不自动复制或进入另存为。允许同船体不同 ID 的蓝图参与对比。同一蓝图调整配置沿用单船装备预览功能。默认候选筛选同样排除 A；只有没有候选时创建的空配装 B 是无保存目标的新方案，不能把空 ID 当作双方同一蓝图；同一保存记录的检查仅针对明确的已保存身份。所有蓝图加载路径维持双方已保存 ID 不同的约束。保存目标被删除后保留工作副本并转为另存为，不匹配其他同船记录。

## 退出、替换和会话失效

统一使用显式意图（退出保留 A／退出保留 B／替换 B）及待关闭侧列表，不以 activeSide 代替关闭侧。

| 意图 | 检查对象 | 完成结果 |
|---|---|---|
| 退出对比 | B | A 保留为单船 |
| 保留 B 返回单船 | A | B 连同身份、基线成为单船 |
| B 更换船型 | 旧 B | 新船型最新创建的非 A 蓝图；无候选则空配装，两者均为 clean 基线 |
| B 载入蓝图 | 旧 B | 安装已选保存蓝图，重查身份冲突 |

关闭侧 clean 直接继续；dirty 时明确保存／放弃／取消。保存失败或命名取消均不释放上下文；放弃仅释放关闭侧；取消不改变布局。保留侧永远不隐式保存或从磁盘重载。

B 更换船型或载入蓝图先取得有效候选：船型必须存在，选择当前船型直接结束且不重置；蓝图须存在且不能与 A 同 ID。随后保护旧 B，最后再次校验并原子替换。更换船型按目标 shipId 选最新创建的非 A 保存蓝图，无候选才创建空配装；不迁移旧 B 装备。手动载入蓝图使用选定记录配装。已有记录绑定其保存身份和 clean 基线，新建空配装取 clean 基线但保存资格明确为另存为，用户后续修改才产生 dirty。候选选择在替换提交前按当前蓝图库再次解析，避免使用旧列表中的失效对象。选择被取消时无需动旧 B。退出成功后清除对比 UI 状态并重新显示保留方案的材料。

审查现有新建、加载、删除、版本切换入口。任何将丢弃两侧的动作收集两侧 dirty，按固定 A→B 次序处理；取消中止切换但不撤销先前已明确成功的保存。全会话 dirty 聚合用于离开保护，activeSide dirty 只用于保存按钮与当前编辑状态。不得让版本设置弹窗只保存或检查其中一侧。

## 实施顺序与风险

先建立显式方案上下文与领域计算，再接入 presenter 和 UI，最后连接保存／退出命令。优先复用已有装备规则，不重写游戏公式。

主要风险是全局 currentShip/blueprint 隐式依赖、saveAs 引用共享、dirty 基线串用、B 计算使用 A 船体以及版本切换遗漏隐藏侧。以针对性 Unit 验证这些边界；UI 行为验证另由 x4-e2e-test 流程规划。现有调试日志不在本次设计中清理，Rust 未变化不得运行 build-rust。

### 默认名称补充（2026-11-12）
Workspace presenter 以当前侧状态标签生成默认名称，并扫描保存记录确定首个可用正整数；无状态标签的干净空方案使用空配。工具栏复用同一方法，取消船型前缀。命名只用于未命名方案，保存身份仍由 ID 决定，不修改旧记录。

### 蓝图删除修正
删除入口显式传入侧，store 拒绝另一侧有效保存身份。对比删除在持久化成功后清空当前侧名称与保存身份、预设标记，保留配装并设置 dirty。菜单以当前保存身份强高亮、另一侧身份弱高亮，禁用另一侧删除按钮；不再使用 guardSession 保护未丢弃的工作副本。两侧状态标签共用判定，删除空配也显示自定义。

### 预设状态显示修正
已有保存目标时应用预设，保留名称和 saveTargetId，清空 loadedBuiltInPreset 与预设快照，使用原保存基线计算 dirty；标题和当前菜单高亮继续指向已保存蓝图，实际变化显示红点。无保存目标时才记录预设状态，getPlanPresetId 返回未修改预设身份供 presenter 显示预设名、高亮及免红点。两侧一致。另一侧有效保存目标仍弱高亮并禁止选择／删除。菜单组和行统一占满宽度，背景及悬停效果放在整行容器，包含收藏和删除按钮。

### 同侧具体槽位切换
Fit 的 openPicker 允许选择器属于当前侧时重新指定 expandedSlotKey；workspace 的 openPicker 分别检查命名／保护弹窗、另一侧选择器和首次激活，允许同侧重入。新槽位事件更新类型、装备和护盾标识，现有 pickerTarget watcher 重置候选与预览。大类型切换仍执行原 closePicker；保存、退出和跨侧切换限制不变。

### 候选校验时序
切换具体槽位时，槽位类型／当前装备与 pickerTarget 经不同更新链路同步。候选合法性校验 watcher 使用 post flush，等待新槽位及筛选重置完成，避免以旧尺寸或旧筛选结果误清空新槽位已安装装备。无需定时器或新增状态层。

### 标题保存与菜单另存为
标题用共享边框的 flex 容器包裹独立保存按钮和菜单按钮，避免嵌套 button；B 容器 row-reverse，保存 SVG 保持原向，原菜单箭头继续镜像。Fit presenter 的 saveCurrentBlueprint 显式传入 side，先关闭菜单，再调用 workspace.save(side, saveAs)，复用现有保存及 SmartSaveDialog。菜单另存为单独分组，与预设及保存列表分隔；锁定时禁用两入口。

### 另存名称生成
workspace getDefaultName 去掉名称尾部空白加数字序号后寻找首个未占用正整数，同时排除当前工作名称。已保存方案的 SmartSaveDialog initialName 使用该建议值；context.name 仍保留原名用于保护提示和普通保存。未命名预设继续使用配装状态编号，未保存的有名草稿保留草稿名。

### 站内删除确认
复用通用 ConfirmDialog 展示纯 UI，workspace presenter 捕获删除侧、sessionId、记录 ID 和名称并锁定操作。Fit 菜单只请求确认，确认时重新验证会话且由 store 检查另一侧占用；取消不写入，失败保留弹窗并显示错误。弹窗 Teleport 至 body，层级高于菜单，样式与 SmartSaveDialog 一致，不改变保存弹窗策略。

### 筛选、弹窗与操作对齐的最终规则
筛选候选 watcher 仅负责页码有效性，不再 emit null 清除选中装备；Vue 根据候选 ID 高亮，选中项不在过滤结果中时自然无高亮，恢复显示时自动高亮。原装备详情逻辑保持。移除已无用途的 presenter emit 参数，按钮事件仍在 Vue 发出。
SmartSaveDialog 遮罩监听 Escape 并发出既有 close，复用取消路径。保护标题使用独立短文案，正文由 presenter 组合侧与蓝图名。
复用 MetricsPanel 的 header-actions 插槽，标题行采用对称网格，将两个短按钮排列在中缝两侧；按钮内侧边缘与两列属性条内侧对齐，保留标题及简略／详细控件，不增加额外操作行。保存按钮框内增加居中的既有 divider，与右侧布局一同镜像。

### 交互复检修正
- selectingShip 保存目标侧而非布尔值，A／B 共用原选型组件；确认候选后 guard 只处理该侧。store.replacePlanShip 共用候选解析并排除另一侧保存身份，独立替换 A 或 B。旧全会话换船入口不再用于标题换船。
- Fit 的目标 watcher 在分组映射完成后，同步调用已有 picker-open 事件以更新当前装备、类型、护盾标识与默认候选，不能仅更新 pickerTarget。
- SmartSaveDialog 无输入时焦点移到 dialog 根元素；有输入仍选中名称。
- 属性模式存于 workspace presenter，经 Stats 绑定 MetricsPanel 的可选 mode model；MetricsPanel 仅在原 mode 不属于新 views 时恢复默认。
- Workspace 是多根组件，选型隐藏使用父级真实 DOM 容器，避免 v-show 落在 fragment 上失效。

### 混合分组保留意图
复用已有 __mixed__ 标识贯穿 Fit 默认候选与 workspace，不再转为 null。mixed 表示无选择，preview 返回 null，确认只关闭选择器；null 仅表示空槽位选择，仍走现有预览及赋值。无需新增界面或状态层，具体装备、空组行为不变。

### 预设补给完整替换
保留 store 原有预设构造和完整 storage 替换行为，不引入合并继承。presenter 初始化时 countermeasure 为 null 必须同步 localCountermeasure 为 0，防止旧值显示及后续 saveToBlueprint 写回。
