# x4-sector 需求说明（最终实现态）

## 目标
在“星区总览”模式下提供可用的星区管理与补给站视图能力，且不改动现有模块主命名。

## 当前范围

### 1. 星区管理
- 支持创建任意数量星区。
- 支持重命名、删除、排序星区。
- 支持将空间站拖拽分配到目标星区。
- 新建空间站默认进入“未分配空间站”。

### 2. 拖拽与顺序
- 星区支持拖拽排序（移动语义）。
- 空间站支持拖拽移动到星区或未分配区。
- Tab 取消拖拽排序，顺序由“星区顺序 + 星区内站点顺序”驱动。

### 3. 补给站入口与页面
- 每个有空间站的星区在 Tab 上显示一个虚拟补给站入口。
- 补给站 Tab 标题显示所属星区名称，颜色与普通站点 Tab 一致（不单独染绿）。
- 点击补给站 Tab 进入整页补给站视图（不是右侧局部面板）。
- 点击总览 Tab 返回总览页面。
- 补给站页面三栏布局：
  - 左栏：建筑区（自动仓储模块规划）
  - 中栏：资源视图（复用帝国资源视图组件）
  - 右栏：建造材料区（复用空间站建造材料/时间/体积仪表盘）
- 三栏宽度比例与主站点视图一致：`3 / 5 / 4`，`gap-8`。
- 补给站态 Context 工具条显示种族选择，并支持直接编辑当前星区名。

### 4. 资源统计口径
- 星区总览资源视图：统计当前 empire 全部空间站。
- 补给站资源视图：仅统计该补给站所属星区内的空间站。
- 资源视图 UI 与交互完全复用帝国资源视图（数量/经济切换、分组样式一致）。
- 补给站新增“仓储视图”：
  - 使用与资源/资金视图相同的资源集合。
  - 不分组，顺序采用“其他视图分组顺序 + 组内顺序”拼接后的线性顺序。
  - 每个资源总需求：`max(Σ产出仓储体积, Σ消耗仓储体积)`。
  - 单站静态值基于 `netRate`：
    - `静产出 = max(netRate, 0)`
    - `静消耗 = max(-netRate, 0)`
  - 单站体积：
    - `产出仓储体积 = 静产出 × unitVolume × primaryProductBufferHours`
    - `消耗仓储体积 = 静消耗 × unitVolume × resourceBufferHours`
  - 展示排版对齐空间站仓储视图（无按钮、总项无占位）。

### 5. Store 层内部计算
- `useEmpireStore` 中独立计算全部星区内部数据，并保存为 `Map`。
- 每个星区包含：
  - 规划输入（本地站点 ID 等）
  - 本地聚合流量（用于补给站资源视图）
  - 仓储视图分项与总量（用于补给站仓储视图）

### 6. 建筑区与建造材料区复用
- 建筑区根据仓储总需求自动反推仓储模块数量（复用空间站选型规则：优先种族 L 仓储，再回退通用/最大容量）。
- 建造材料区直接复用空间站右侧仪表盘组件，并以建筑区自动模块作为输入。
- 在补给站场景下隐藏工人视图，仅保留建造材料、体积、时间视图。

### 7. 版本与兼容
- Empire 存储版本升级为 `4`。
- 旧数据迁移、导入导出按当前最终结构执行。

### 8. 泊位与吞吐量（空间站侧）
- ContextBar 显示“单泊位吞吐量”，公式固定为：`transportShipCapacity * 15`，单位 `m³/h`。
- `x4_data_processor.py` 在解析 `class="pier"` 模块时，统计 `<connections>` 下 `<connection>` 数量，写入 `dockingCount`。
- `X4Module` 增加 `dockingCount` 必填字段（无 `null/undefined`）。
- 空间站泊位需求计算口径：
  - 先按运输类型分桶：`container / solid / liquid`。
  - 各类型分别计算泊位需求：`ceil(typeThroughput / singleBerthThroughput)`。
  - 最终泊位需求为三类求和。
- 空间站自动补泊位模块选型优先级：
  - 优先：`plannedModules` 中“同种族”泊位模块；
  - 次选：`plannedModules` 中第一个泊位模块；
  - 兜底：对应种族 E 泊位（`harbor_03`）。
- 泊位模块承载能力统一使用 `dockingCount`。

## 明确不做
- “星区连接（link）”功能已在开发中途取消，当前版本不提供（UI 与 store 操作均已关闭）。
