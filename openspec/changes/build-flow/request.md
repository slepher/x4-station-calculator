# Build Flow

## 目标

在 `logic-flow` 页面新增“建筑产线区”，从现有产线组自动推导出与建筑原材料相关的产线、材料标签与匹配关系，帮助用户为建筑材料建立来源分配，并在界面上可视化这些分配连线。

本次变更只新增一套独立的建筑流规划视图与关系存储，不改变现有 `logicFlow.groups`、节点、血统、隔离、拖拽投放等既有数据与行为。

## 已确认方案（审核重点）

### 数据来源与推导口径

- 现有产线的基础单位是 `ProductionLineGroup`，不是单个 `FlowNode`。
- 某条产线的“主要产品”定义为该 group 内 `source === 'manual' && !isIsolated` 的节点产物。
- “需求原材料”定义为：对现有所有产线组内参与产线建造的模块求 `buildCost` 后汇总得到的材料总表。参与统计的模块口径为：group 内所有 `!isIsolated` 且对应模块 `tier > 0` 的节点（tier 0 的 ware 不是可建造模块，不纳入 buildCost）。
- 某条产线是否进入“建筑产线区”的条件为：该产线的主要产品中，至少有一个 `wareId` 命中“需求原材料”。
- “产线原材料”定义为：该产线的主要产品中，命中“需求原材料”的那些产物；它们代表这条产线可提供的建筑原材料。
- “产线建材”定义为：建造该产线本身所需的材料，即该产线自身模块（`!isIsolated` 且 `tier > 0`）`buildCost` 的材料集合与“需求原材料”的交集。
- “现产原材料”定义为：建筑产线区内全部产线的“产线原材料”去重并集。

### 视图结构

- 在 `logic-flow` 页面新增一个独立的“建筑产线区”。
- 页面布局顺序固定为：
  - 顶部：`CandidateZone`
  - 中部：`BuildFlowZone`
  - 底部：`PlanningZone`
- 建筑产线区内，每条入选产线显示为一个 card。
- 每个产线 card 内至少显示两类标签：
  - `产线原材料` 标签：该产线可提供的建筑原材料。
  - “产线建材” 标签：建造该产线自身所需且属于“现产原材料”的建材。
- 建筑产线区内还需单独显示一个“产出区” card。
- “产出区” card 内的标签是“现产原材料”。
- 建筑产线区不提供手动折叠/展开能力。
- 当用户进入规划区相关拖拽流程时，`BuildFlowZone` 必须自动隐藏；拖拽结束后自动恢复显示。该隐藏规则的目的是避免 `build-flow` 干扰与其无关的规划拖拽交互。

### 交互与关系存储

- 用户可从某条产线 card 的“产线原材料”标签发起拖拽。
- 用户可将该标签投放到以下同 `wareId` 目标：
  - 某条产线 card 内的同名“产线建材”标签。
  - “产出区” card 内的同名“现产原材料”标签。
- 匹配严格按 `wareId` 判断，不按文案文本判断。
- 用户 hover 在“产线原材料”标签上时，应像现有规划区元素一样出现 `+` 号。
- 点击 `+` 后弹出目标菜单（从标签右侧弹出，空间不足时向左，与候选区弹出策略一致）；菜单项显示目标产线名称或“产出区”，后跟 ware 名称作为辅助说明。
- 点击菜单项与拖拽投放效果一致。

### 关系规则

- 拖拽或菜单绑定不会修改当前产线数据，不改变现有 group / node 的任何业务字段。
- 系统需单独存储建筑流绑定关系，供其他位置后续复用。
- 建筑流关系属于单条 `logic-flow plan` 的内容，必须跟随该 `LogicFlowPlan` 一起保存、另存为、加载和删除。
- 同一个“产线原材料”可以出现在多个来源 card 中。
- 但每个“产线建材”目标标签只能绑定唯一来源产线。
- 每个“现产原材料”目标标签也只能绑定唯一来源产线。
- 当用户用新的来源产线绑定同一个目标标签时，新绑定覆盖旧绑定。
- 目标标签需要支持解绑。

### 连线反馈

- 当用户通过拖拽或菜单成功建立关系后，界面上必须立即新增一条有向连接线。
- 连接线方向固定为：
  - 来源端：产线 card 内的“产线原材料”标签。
  - 目标端：某个“产线建材”标签或“现产原材料”标签。
- 同一个来源标签可以向多个不同目标画线。
- 同一个目标标签在任意时刻只保留一条入线，覆盖时旧线消失、新线生效。
- 解绑后，对应连线同步消失。

## 边界

### In Scope

- 新增建筑产线区的数据推导
- 新增建筑流关系的方案内独立存储结构
- 新增基于 `wareId` 的目标匹配逻辑
- 新增拖拽绑定、菜单绑定、覆盖、解绑
- 新增建筑流关系的有向连线显示
- 新增规划拖拽期间 `BuildFlowZone` 的自动隐藏规则

### Out of Scope

- 修改现有 `logicFlow.groups` / `FlowNode` 的业务结构
- 改写现有候选区与规划区的核心拖拽规则
- 调整现有 bloodline / isolate / auto promote / planning zone 的业务语义
- 编写测试代码或执行测试

## 验收标准（DoD）

1. `logic-flow` 页面新增独立“建筑产线区”与“产出区” card。
2. 建筑产线区仅基于现有 `ProductionLineGroup` 推导，不直接修改现有产线数据。
3. “主要产品”严格按 `source === 'manual' && !isIsolated` 节点定义。
4. “需求原材料”来自现有产线自身模块（`!isIsolated` 且 `tier > 0`）`buildCost` 的汇总。
5. 每个入选产线 card 正确显示“产线原材料”和“产线建材”两类标签。
6. “现产原材料”正确显示全部入选产线的产线原材料并集。
7. 仅允许同 `wareId` 的来源标签与目标标签建立关系。
8. 菜单绑定与拖拽绑定写入同一套独立关系数据。
9. 同一目标标签再次绑定时覆盖旧绑定。
10. 目标标签支持解绑，解绑后关系数据与连线一并移除。
11. 成功绑定后界面立即显示从来源标签指向目标标签的有向线。
12. 覆盖与解绑时，连线状态与最终关系保持一致。
13. 建筑流关系跟随单条 `LogicFlowPlan` 保存，不与其他方案串联。
14. `BuildFlowZone` 常规状态下常显，但在规划区相关拖拽期间自动隐藏，且不影响现有拖拽流程。
