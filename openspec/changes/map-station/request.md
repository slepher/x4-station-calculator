# map-station 需求说明

## 目标
为 map 页面增加“空间站”工作面板，用于在星图中放置当前 empire 的空间站与星区中转点（sector）。
用户可以在面板打开时查看当前 empire 的所有 `sector + station`，将对象拖入地图中的目标星区，并在星区内继续微调坐标；坐标以原始坐标保存到 empire 持久化数据中。

## 已确认方案（审核重点）

### 1. 入口与工作态布局
- map 页面左下角新增“空间站 + 图标”入口按钮。
- 入口按钮与左上角现有资源过滤入口保持对称语义，采用文字 + 图标形式。
- 点击入口后，页面切换为与资源过滤面板同层级的左侧工作面板布局，而不是新页面或独立弹窗。
- 关闭面板后，地图上的空间站相关覆盖内容全部隐藏。

### 2. 面板对象范围
- 面板展示对象来自当前 `activeEmpire`。
- 可布置对象包括：
  - 当前 empire 的全部 `stations`
  - 当前 empire 的全部 `sectors`，其在地图放置语义中表示“星区中转点”
- 地图底图仍然使用全量星图数据；可拖入对象只来自当前 empire。
- 空间站面板自身包含独立搜索框，搜索范围仅限面板对象，不影响地图右上角全局星区搜索。

### 3. 拖放与微调行为
- 用户可将 `station` 或 `sector` 从面板拖入地图中的任意目标星区。
- 放入目标星区后，需要确定该对象在目标星区内的二维位置。
- 拖入后对象仍可继续在星区内微调位置。
- 面板打开时，已放置对象可见且可再次拖动微调。
- 面板关闭时，相关对象隐藏且不可继续操作。

### 4. location 数据结构与继承
- `location` 可以加到 `station`，也可以加到 `sector`。
- `location` 结构为：
  - `cluster_id`
  - `sector_id`
  - `pos: { x, z }`
  - `sunlight`
  - `resources: string[]`
- `resources` 只保存 `ware` id，不保存复杂对象结构。
- `sunlight` 与 `resources` 由目标地图星区自动继承并快照保存，不允许手填。
- `sector.location` 的语义是“该星区中转点在地图中的放置位置”；其中 `location.sector_id` 指向被放入的目标地图星区。

### 5. 坐标保存规则
- 坐标保存使用目标星区的原始坐标系，不使用归一化坐标。
- `pos` 使用 `{ x, z }` 命名。
- 再次拖放同一对象时，更新既有位置，不创建副本。
- 每个 `station` 仅允许一个地图位置；每个 `sector` 中转点也仅允许一个地图位置。

### 6. 清除与取消放置
- 面板内需要提供“清除位置 / 取消放置”操作。
- 用户可以移除已有 `location`，使对象恢复为未放置状态。
- 重新拖到其他位置时，视为更新已有位置。

### 7. 面板显示精简与滚动
- 空间站面板列表项不显示 `station`、`sector transit`、`未放置` 这类状态字样。
- 列表项保留图标、名称、拖动手柄与必要操作，不再显示“拖动到地图”文案。
- 面板改为整个主体区域共享一根滚动条，而不是“未放置 / 已放置”两个区块各自独立滚动。
- 滚动条风格需要与当前面板黑底 + 琥珀色视觉一致。

### 8. 已放置列表点击行为
- 点击“已放置”区块中的 `station` 或 `sector transit` 时，地图需要 focus 到其目标地图星区。
- focus 效果与点击地图右上角搜索结果时保持一致，即复用相同镜头定位逻辑。
- 已放置项展示目标地图星区的本地化名称，不显示 `sector_id`。
- 已放置项不显示坐标 `{x, z}`。

### 7. 持久化与 dirty 规则
- `location` 变动视为 empire 可编辑输入变动。
- `station.location` 或 `sector.location` 变动后，empire 本身需要进入 dirty 状态，可执行保存。
- `location` 作为 empire 持久化结构的一部分写入 `x4_empire_data`。

## 边界

### In Scope
- map 页面空间站入口按钮与左侧工作面板。
- 当前 empire 的 `stations` 与 `sectors` 列表展示。
- `station` / `sector` 拖入地图目标星区并记录原始 `{x, z}` 坐标。
- 已放置对象在面板打开时的可见、拖动微调与清除位置操作。
- `location` 写入 empire 持久化数据，并参与 dirty 判断。

### Out of Scope
- 修改资源过滤面板的筛选规则与表现。
- 修改地图底图、cluster/sector 基础渲染算法。
- 为 `resources` 保存丰度、颜色、等级等复杂结构。
- 支持一个对象在地图上出现多个副本。

## 验收标准（DoD）
- map 页面左下角存在“空间站 + 图标”入口按钮。
- 点击入口后，页面进入左侧工作面板布局，并显示当前 empire 的 `sector` 与 `station` 对象。
- 左侧工作面板 SHALL 采用方案 A 结构，至少包含“未放置”和“已放置”两个区块。
- 空间站面板 SHALL 提供仅作用于面板对象的搜索框，并支持一键清空搜索内容。
- 用户可将任一 `station` 拖入任意地图星区，并在该星区内继续拖动微调。
- 用户可将任一 `sector` 作为中转点拖入任意地图星区，并在该星区内继续拖动微调。
- 对象放置后，系统 SHALL 为对应 `station` 或 `sector` 写入 `location`，其中包含 `cluster_id`、目标 `sector_id`、原始 `pos{x,z}`、`sunlight` 与 `resources:string[]`。
- `sunlight` 与 `resources` SHALL 自动继承自目标地图星区；`resources` 仅包含 ware id。
- 再次拖放同一对象时，系统 SHALL 更新原有 `location`，而不是创建副本。
- 面板内存在清除位置/取消放置操作，执行后对象 SHALL 移除 `location`。
- 面板对象列表 SHALL 使用统一滚动容器与风格化滚动条，不为“未放置 / 已放置”分别创建独立滚动区域。
- 面板对象列表 SHALL 使用拖动手柄作为拖拽入口提示，不显示“拖动到地图”文案。
- 点击已放置对象时，系统 SHALL focus 到其目标地图星区，且效果与地图搜索结果点击保持一致。
- 已放置对象 SHALL 显示目标地图星区名称，而不是 `sector_id`，并且 SHALL NOT 显示坐标。
- 关闭面板后，地图上的空间站相关覆盖内容 SHALL 隐藏，但基础星图仍显示。
- 任意 `location` 变动后，empire SHALL 进入 dirty 状态，并可保存到 `x4_empire_data`。
