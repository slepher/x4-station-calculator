# 需求说明：import-export

## 目标
为系统新增统一的导入/导出能力，支持按模块导入数据，并在导入时执行模块迁移、覆盖/增量策略、`activeId` 更新策略和页面刷新策略。

## 已确认方案（审核重点）
1. **导入模块范围**
   - 本期导入覆盖 3 个模块：`x4_empire_data`、`x4_logic_flow_plans`、`x4_ship_blueprints`。
   - 每个模块独立执行导入流程，互不阻塞；单模块失败不应污染已成功模块。
2. **模块导入统一流程**
   - 步骤 1：先执行 `migrate(moduleData)`。
   - 步骤 2：根据“增量导入”选项执行覆盖或增量。
   - 步骤 3：按规则决定是否更新该模块 `activeId`。
   - 步骤 4：若 `activeId` 更新，按当前页面上下文刷新对应 store/UI。
3. **迁移策略**
   - `x4_empire_data`：需要真实迁移（支持 v1 -> v2）。
   - `x4_logic_flow_plans`：提供空迁移入口，当前 no-op。
   - `x4_ship_blueprints`：提供空迁移入口，当前 no-op。
4. **覆盖与增量策略**
   - 覆盖：清理当前模块 store 数据，再导入。
   - 增量：在当前模块 store 数据上追加导入，并对导入数据重新生成 ID，避免与现有数据冲突。
5. **`activeId` 更新规则**
   - 覆盖导入：直接更新为导入结果中的 `activeId`（若合法）。
   - 增量导入：仅当满足以下任一条件才更新：
     - 当前 `activeId` 为空；
     - 当前 `activeId` 对应数据为空且当前模块 `isDirty=false`。
   - 不满足条件时保持当前 `activeId` 不变。
6. **Empire 的联动规则**
   - 当 `x4_empire_data.activeId` 被更新时，同步按导入结果更新 `activeStationId`。
7. **页面刷新规则**
   - 仅在模块 `activeId` 发生变更后触发对应刷新。
   - 刷新目标应与当前页面一致：生产页刷新 Empire/Station 上下文，逻辑组网页刷新 Logic Flow 上下文，Ship Build 页刷新蓝图上下文。
8. **导出策略**
   - 导出按模块组织，导出结果包含模块数据与版本字段，供后续导入流程直接消费。
9. **UI 入口与流程**
   - 导入导出入口使用 TabBar 上现有“导入 / 导出”按钮。
   - 点击导出后打开导出弹窗（独立 Vue 组件），而非直接下载。
   - 导出弹窗需展示 3 个模块（帝国/flow/ship）的数据条数统计。
   - 导出弹窗需提供“导出文件名”输入框，默认值为系统生成文件名，用户可修改。
   - 弹窗底部提供“取消 / 下载”按钮；下载按钮 UI 为 `[[下载图标] 下载]`。
   - 点击“下载”后按输入文件名导出 JSON（无 `.json` 后缀时自动补全）并触发浏览器下载。
   - 点击导入后显示文件上传界面，用户上传 JSON 后进入导入配置步骤。
10. **导入配置项（上传后）**
   - 提供“是否覆盖”选项（覆盖 / 增量）。
   - 展示 JSON 中包含的模块统计：
     - `x4_empire_data`（帝国）及其数据条数
     - `x4_logic_flow_plans`（flow）及其数据条数
     - `x4_ship_blueprints`（ship）及其数据条数
   - 模块级多选：用户可选择本次要导入哪些模块。
   - 当“是否覆盖 = 覆盖”时，模块多选默认全选。

## 边界
### In Scope
- 新增模块化导入流程（迁移、覆盖/增量、`activeId` 规则、页面刷新）。
- 新增模块化导出数据结构与导出入口能力。
- 为非 Empire 模块提供迁移扩展点（no-op）。
- 新增导入文件上传与上传后配置 UI（覆盖选项、模块统计、模块级多选）。

### Out of Scope
- 不引入云端同步、账号体系或远程存档。
- 不在本期实现额外历史版本链路（除 Empire v1->v2）。
- 不改变现有业务计算口径（产线分析、配装计算等）。

## 验收标准（DoD）
1. 系统可按模块执行导入，每个模块均遵循“迁移 -> 覆盖/增量 -> `activeId` 决策 -> 刷新”流程。
2. `x4_empire_data` 导入可处理 v1->v2，其他模块迁移入口存在且可运行 no-op。
3. 增量导入时，导入对象 ID 全部重生且无冲突。
4. 覆盖导入总是以导入结果替换当前模块数据并按规则更新 `activeId`。
5. 增量导入仅在“`activeId` 为空或空且不脏”条件下更新 `activeId`。
6. Empire 在 `activeId` 更新时同步更新 `activeStationId`。
7. `activeId` 更新后，当前页面可见内容与新上下文一致（无手动刷新要求）。
8. 导出结果可作为导入输入被同版本系统正确识别。
9. 用户可从 TabBar 导入按钮上传 JSON，并看到模块统计与模块级多选。
10. 覆盖模式下模块多选默认全选，用户仍可手动取消部分模块。
11. 导出按钮打开导出弹窗，弹窗内可编辑文件名并通过“下载”按钮导出 JSON 文件。
