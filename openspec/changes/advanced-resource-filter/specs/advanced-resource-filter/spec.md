# Advanced Resource Filter Specification

## Purpose
定义地图资源过滤区的高级组合过滤能力，包括简单/高级双模式、资源星区集合与共同中转核心候选的结果模型、极大候选去冗余，以及高级模式评分排序规则。

## ADDED Requirements

### Requirement: Simple And Advanced Filter Modes
系统 MUST 在地图资源过滤区提供 `简单` 与 `高级` 两种过滤模式，并使用独立组件实现两套交互。

#### Scenario: 切换过滤模式
- **前提** 用户已打开地图资源过滤区
- **当** 用户点击 `简单` 或 `高级` Tab
- **那么** 系统 SHALL 切换到对应模式的独立组件
- **并且** 系统 MUST NOT 将简单模式内部状态直接映射为高级模式状态
- **并且** 系统 MUST NOT 将高级模式内部状态直接映射为简单模式状态

#### Scenario: 模式状态独立保留
- **前提** 用户分别在 `简单` 与 `高级` 模式下输入过筛选条件
- **当** 用户在两个模式之间往返切换
- **那么** 系统 SHALL 恢复各自模式切换前的输入状态
- **并且** 系统 SHALL 恢复各自模式对应的候选结果语义

### Requirement: Advanced Tag Group Semantics
高级模式 MUST 支持多个 `tag` 组，并按组内 `AND`、组间 `AND` 规则判定资源星区覆盖关系。

#### Scenario: 组内 AND
- **前提** 某 `tag` 组包含多个资源 `tag`
- **当** 系统判断某资源星区是否命中该组
- **那么** 该星区 MUST 同时满足该组内全部 `tag`

#### Scenario: 组间 AND
- **前提** 高级模式下存在多个 `tag` 组
- **当** 系统判断某候选是否有效
- **那么** 候选中的资源星区集合 MUST 合起来覆盖全部 `tag` 组

#### Scenario: 单星区可覆盖多个组
- **前提** 某资源星区同时满足多个 `tag` 组
- **当** 系统构造高级模式候选
- **那么** 系统 SHALL 允许该星区同时为多个组提供覆盖

#### Scenario: 日光属于组内条件
- **前提** 高级模式中的某个 `tag` 组启用了 `日光`
- **当** 系统判定星区是否命中该组
- **那么** 系统 SHALL 使用该组自己的日光阈值作为该组条件的一部分
- **并且** 系统 MUST NOT 将日光实现为高级模式全局过滤条件

### Requirement: Advanced Transit Permission Toggle
高级模式 MUST 提供 `允许中转` checkbox，并用它约束共同中转核心候选池。

#### Scenario: 勾选允许中转
- **前提** 用户位于高级模式
- **并且** `允许中转` checkbox 处于勾选状态
- **当** 系统计算共同中转核心候选
- **那么** 系统 SHALL 允许从任意满足跳数约束的星区中选择共同中转核心

#### Scenario: 取消勾选允许中转
- **前提** 用户位于高级模式
- **并且** `允许中转` checkbox 处于未勾选状态
- **当** 系统计算共同中转核心候选
- **那么** 系统 SHALL 仅允许从命中的资源星区中选择共同中转核心

### Requirement: Advanced Tag Groups Expand In Place
高级模式的每个 `tag` 组 MUST 在组列表中原位展开编辑，而不是使用独立编辑区。

#### Scenario: 默认显示摘要态
- **前提** 用户位于高级模式且某 `tag` 组未进入编辑态
- **当** 系统渲染该组
- **那么** 系统 SHALL 显示该组当前已选 `tag` 列表
- **并且** SHALL 显示 `编辑` 按钮
- **并且** MUST NOT 额外显示独立标题栏

#### Scenario: 点击编辑后原位展开
- **前提** 用户位于高级模式且某 `tag` 组处于摘要态
- **当** 用户点击该组的 `编辑`
- **那么** 该组 SHALL 在原位置切换为展开编辑态
- **并且** 系统 MUST NOT 在组列表之外新增独立编辑区

#### Scenario: 同时仅允许一个组展开
- **前提** 当前已有一个 `tag` 组处于展开编辑态
- **当** 用户尝试展开另一个 `tag` 组
- **那么** 系统 SHALL 保证同一时间仅有一个组保持展开编辑态

#### Scenario: 组块优先单行布局
- **前提** 某 `tag` 组处于摘要态
- **当** 系统渲染该组
- **那么** 系统 SHALL 优先让已选 `tag` 列表与 `编辑` 按钮在同一行内显示
- **并且** 当 `tag` 数量过多时，SHALL 允许在组块内部自然换行

#### Scenario: 摘要态资源 tag 使用资源色填充
- **前提** 某 `tag` 组处于摘要态
- **当** 系统渲染该组内已选资源 tag
- **那么** 系统 SHALL 使用对应资源色填充这些 tag
- **并且** 系统 SHALL 保持文字与边框在深色背景上的可读性

#### Scenario: 组内保留所有项联动下拉
- **前提** 某 `tag` 组包含两个或以上普通资源 `tag`
- **当** 系统渲染该组的展开编辑态
- **那么** 系统 SHALL 显示 `所有项` 丰度联动下拉
- **并且** 用户修改该下拉时，系统 SHALL 批量更新该组内全部普通资源的最低丰度
- **并且** 当组内普通资源当前最低丰度不一致时，系统 SHALL 显示 `混合` 状态

### Requirement: Advanced Candidate Uses Resource Set And Hub Candidates
高级模式的结果单位 MUST 是“资源星区集合 + 共同中转核心候选集合”，而不是单个 sector。

#### Scenario: 以共同核心收敛资源星区
- **前提** 已知某中转核心星区 `H` 与若干资源星区的跳数关系
- **当** 系统构造以 `H` 为核心的原始候选
- **那么** 只有满足 `dist(resourceSector, H) <= N` 的资源星区 SHALL 被纳入
- **并且** 这些资源星区 MUST 合起来覆盖全部 `tag` 组

#### Scenario: 相同资源集合的多个核心合并
- **前提** 两个或多个中转核心对应相同的资源星区集合
- **当** 系统整理高级模式结果
- **那么** 系统 SHALL 将这些核心合并到同一个结果项中
- **并且** 结果项 SHALL 以单一资源星区集合呈现
- **并且** 结果项 SHALL 附带全部共同中转核心候选

### Requirement: Advanced Pie Fill Aggregates Matched Group Resources
高级模式地图填充 MUST 按星区实际命中的多个 `tag` 组汇总资源切片。

#### Scenario: 单星区命中多个 tag 组时叠加切片
- **前提** 某资源星区同时命中多个 `tag` 组
- **当** 系统生成该星区的高级模式地图 fill
- **那么** 系统 SHALL 汇总这些已命中组对应普通资源的并集切片
- **并且** 系统 MUST NOT 仅显示其中单一组的资源切片

#### Scenario: 复用现有 fill 协议
- **前提** 高级模式存在资源命中星区
- **当** 系统向地图画布输出表现层数据
- **那么** 系统 SHALL 复用现有 `SectorResourceFill` 协议
- **并且** 允许输出 `solid` 或 `pie` 两种 fill 模式

#### Scenario: 资源星区六边形显示命中组序号
- **前提** 某资源星区已在地图上被资源 fill 染色
- **当** 系统渲染该资源星区六边形
- **那么** 系统 SHALL 在六边形底边内侧上方中央显示命中组序号 badge
- **并且** 组序号 SHALL 按当前高级模式组顺序从 `1` 开始编号

#### Scenario: 中转星区不显示命中组序号
- **前提** 某星区仅作为中转候选被高亮
- **当** 系统渲染该中转星区
- **那么** 系统 MUST NOT 为其显示命中组序号 badge

### Requirement: Advanced Result Keeps Only Maximal Resource Sets
高级模式 MUST 删除资源星区集合被其他候选严格全包含的冗余结果，并保留所有互不全包含的候选。

#### Scenario: 删除严格子集候选
- **前提** 候选 A 的资源星区集合被候选 B 严格全包含
- **当** 系统整理最终候选结果
- **那么** 候选 A MUST NOT 进入最终结果

#### Scenario: 保留互不全包含候选
- **前提** 两个候选的资源星区集合互不全包含
- **当** 系统整理最终候选结果
- **那么** 这两个候选 SHALL 同时保留在最终结果中

#### Scenario: 去冗余不比较核心集合
- **前提** 两个候选的资源星区集合相同但共同中转核心候选不同
- **当** 系统整理最终候选结果
- **那么** 系统 SHALL 将其合并为同一结果项
- **并且** 系统 MUST NOT 因核心集合不同而重复展示

### Requirement: Advanced Candidate Score Uses Weakest Group
高级模式候选排序 MUST 使用“每组最佳星区的组内平均 `level`，再取所有组中最低分”的规则，且 `日光` MUST NOT 参与评分。

#### Scenario: 单组分数取最佳星区的平均 level
- **前提** 某候选包含多个资源星区，且某 `tag` 组包含多个资源 `tag`
- **当** 系统计算该 `tag` 组分数
- **那么** 系统 SHALL 在候选资源星区中找出命中该组最好的星区
- **并且** SHALL 使用该星区在该组内各普通资源 `tag` 的 `level` 平均值作为该组分数

#### Scenario: 最终分数取最低组分数
- **前提** 某候选的多个 `tag` 组都已得到组分数
- **当** 系统计算候选最终排序分数
- **那么** 系统 SHALL 取所有组分数中的最低值作为最终分数

#### Scenario: 日光不参与评分
- **前提** 高级模式启用了 `日光` 过滤条件
- **当** 系统计算候选组分数与最终分数
- **那么** 系统 SHALL 仅将 `日光` 用于过滤约束
- **并且** 系统 MUST NOT 将 `日光` 纳入任何 `level` 平均值或最终排序分数

#### Scenario: 仅日光命中也不参与评分
- **前提** 某资源星区仅满足 `日光` 条件，且没有普通资源命中
- **当** 系统计算候选组分数与最终分数
- **那么** 该星区 SHALL 仍可参与过滤命中与候选覆盖
- **并且** 系统 MUST NOT 因该星区的日光值为其生成评分分值

### Requirement: Advanced Results Are Displayed As Candidate Groups
高级模式结果区 MUST 展示候选组，而不是单星区候选列表。

#### Scenario: 结果卡片表达候选组语义
- **前提** 高级模式存在至少一条有效候选
- **当** 系统渲染结果区
- **那么** 每条结果 SHALL 表达该候选的资源星区集合
- **并且** SHALL 表达该候选的共同中转核心候选集合
- **并且** SHALL 表达该候选的排序分数

#### Scenario: 资源星区与中转候选可点击
- **前提** 高级模式结果区已展示候选卡片
- **当** 系统渲染候选内的资源星区和中转候选
- **那么** 系统 SHALL 将它们渲染为可点击 tag

#### Scenario: 候选卡片使用资源与中转类型胶囊
- **前提** 高级模式结果区已展示候选卡片
- **当** 系统渲染资源星区行与中转候选行
- **那么** 系统 SHALL 分别使用 `资源` 与 `中转` 类型胶囊表达这两行语义
- **并且** 系统 MUST NOT 再使用 `中转候选:` 这类说明性标题文本

#### Scenario: 资源与中转类型胶囊保持等宽
- **前提** 高级模式结果区已展示候选卡片
- **当** 系统渲染 `资源` 与 `中转` 类型胶囊
- **那么** 这两类胶囊 SHALL 使用一致的宽度与高度
- **并且** 两行右侧 tag 列表的起始线 SHALL 对齐

#### Scenario: 资源星区 tag 显示命中组序号
- **前提** 某资源星区命中一个或多个 `tag` 组
- **当** 系统渲染该资源星区 tag
- **那么** 系统 SHALL 在 tag 内显示表示命中组的序号 badge
- **并且** 组序号 SHALL 按当前高级模式组顺序从 `1` 开始编号

#### Scenario: 多组命中显示多个独立 badge
- **前提** 某资源星区同时命中多个 `tag` 组
- **当** 系统渲染该资源星区 tag
- **那么** 系统 SHALL 显示多个独立的组序号 badge
- **并且** 系统 MUST NOT 将多个命中组合并为单段难以区分的文本

#### Scenario: 点击整条候选时整体 fit 相关星区
- **前提** 用户点击某条高级候选卡片的整条结果
- **当** 系统处理该候选选择
- **那么** 系统 SHALL 对该候选的 `resourceSectorIds` 与 `hubCandidateSectorIds` 并集执行整体视角 fit
- **并且** 系统 MUST NOT 退化为仅 focus 其中单个 sector

#### Scenario: 整体 fit 保持中央八成可视区边距
- **前提** 用户点击某条高级候选卡片的整条结果
- **当** 系统执行该候选的整体视角 fit
- **那么** 系统 SHALL 使用候选内各星区六边形的实际外接范围合并计算总 box
- **并且** SHALL 以该总 box 的中心作为 fit 后的目标中心
- **并且** SHALL 分别按 `boxWidth * 1.25` 与 `boxHeight * 1.25` 适配 viewport 计算 scale，并取较小值
- **并且** 因此让该候选涉及的全部资源星区与中转星区尽量落入 map viewport 中央 `80%` 的可视区域
- **并且** 系统 MUST NOT 让 fit 结果贴边占满整个 viewport

#### Scenario: 点击其他候选的 tag 时切换并 focus
- **前提** 用户点击某个资源星区 tag 或中转候选 tag
- **并且** 该 tag 所属候选不是当前候选
- **当** 系统处理点击
- **那么** 系统 SHALL 切换到该 tag 所属候选
- **并且** SHALL 触发地图 focus 到被点击的具体星区

#### Scenario: 点击当前候选的 tag 时仅 focus
- **前提** 用户点击某个资源星区 tag 或中转候选 tag
- **并且** 该 tag 所属候选已经是当前候选
- **当** 系统处理点击
- **那么** 系统 MUST NOT 切换当前候选
- **并且** SHALL 触发地图 focus 到被点击的具体星区

#### Scenario: 候选内 tag 点击继续保持单点 focus
- **前提** 用户点击高级候选内的资源星区 tag 或中转候选 tag
- **当** 系统处理该次点击
- **那么** 系统 SHALL 继续对被点击的具体 sector 执行单点 focus
- **并且** 系统 MUST NOT 将这类点击升级为整条候选的整体 fit

#### Scenario: 地图高亮与结果组一致
- **前提** 用户选中某条高级模式候选
- **当** 地图刷新高亮
- **那么** 地图高亮 SHALL 与该候选组语义一致
- **并且** 系统 MUST NOT 退化为仅高亮单个资源星区的表达

#### Scenario: 候选选中后仍显示资源饼图
- **前提** 用户已选中某条高级模式候选
- **当** 地图刷新该候选的资源显示
- **那么** 系统 SHALL 继续显示该候选资源星区的 `solid/pie` fill
- **并且** 系统 MUST NOT 因候选选中态压掉资源饼图

#### Scenario: selected 状态下仍显示资源饼图
- **前提** 某资源星区因候选内 tag 点击进入 `selected` 状态
- **当** 地图渲染该星区
- **那么** 系统 SHALL 继续渲染该星区的资源 `solid/pie` fill

#### Scenario: 切换候选时清理旧的资源 selected
- **前提** 用户曾通过候选内 tag 点击使某个资源星区进入 `selected` 状态
- **并且** 用户随后切换到另一条候选
- **当** 系统刷新新候选的高亮
- **那么** 系统 SHALL 清理旧候选遗留的资源 `selected` 状态
- **并且** 系统 MUST NOT 让旧的单 sector 选中态干扰新候选的资源展示

### Requirement: Advanced Mode Uses Internal Panel Scroll
高级模式 MUST 将滚动限制在右侧过滤区内部，并在刷新后保持滚动位置稳定。

### Requirement: Advanced Jump Limit Control Matches Simple Sunlight Style
高级模式的 `跳数` 输入 MUST 与简单模式日光输入保持同类风格，并与 `允许中转` 同排显示。

#### Scenario: 跳数与允许中转同排
- **前提** 用户位于高级模式
- **当** 系统渲染顶部控制区
- **那么** `跳数` 与 `允许中转` SHALL 位于同一行

#### Scenario: 跳数输入范围固定
- **前提** 用户位于高级模式
- **当** 用户输入或调整跳数
- **那么** 系统 SHALL 将跳数限制在 `1..5`

#### Scenario: 跳数使用日光风格 stepper
- **前提** 用户位于高级模式
- **当** 系统渲染跳数输入
- **那么** 系统 SHALL 使用与简单模式日光输入同类的数字框、suffix 和上下箭头 stepper 风格

#### Scenario: 仅过滤区内部滚动
- **前提** 高级模式右侧过滤内容超过可视高度
- **当** 用户滚动资源过滤面板
- **那么** 系统 SHALL 仅在右侧过滤区内部滚动
- **并且** 左侧地图区域 MUST NOT 因此出现额外滚动条

#### Scenario: 过滤区滚动条符合页面风格
- **前提** 高级模式右侧过滤区出现滚动条
- **当** 系统渲染滚动条
- **那么** 滚动条样式 SHALL 与页面现有风格保持一致

#### Scenario: 刷新后保留滚动位置
- **前提** 用户已滚动到高级模式过滤区中部或底部
- **并且** 当前输入存在待刷新的修改
- **当** 用户点击 `刷新`
- **那么** 系统 SHALL 更新候选结果与地图联动
- **并且** SHALL 保持右侧过滤区原有滚动位置
- **并且** MUST NOT 自动跳回顶部
