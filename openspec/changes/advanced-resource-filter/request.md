# advanced-resource-filter 需求说明

## 目标
在地图界面的资源过滤区中新增“高级”模式，用于支持多 `tag` 组、多资源星区组合和共同中转核心候选的筛选。
同时保留现有单组资源过滤能力，并以 `简单 / 高级` Tab 形式切换，两套模式使用完全不同的 Vue 组件实现且各自保留独立状态。

## 已确认方案（审核重点）

### 1. 模式拆分与入口
- 地图资源过滤区拆分为 `简单` 与 `高级` 两个 Tab。
- `简单` 模式保留现有单 `tag` 组资源过滤语义，使用独立 Vue 组件实现。
- `高级` 模式使用另一套独立 Vue 组件实现，不复用简单模式的内部状态结构。
- 两套模式各自保留自己的表单数据、筛选输入与候选结果；切换 Tab 时不互相覆盖，不自动清空。

### 2. 高级模式的 tag 组语义
- 高级模式允许用户维护多个 `tag` 组。
- 每个 `tag` 组内为 `AND` 关系：一个星区若要命中该组，必须满足该组内全部 `tag`。
- 不同 `tag` 组之间也为 `AND` 关系：最终候选必须覆盖全部 `tag` 组。
- 同一个资源星区允许同时命中多个 `tag` 组。
- `日光` 必须作为组内条件配置，而不是高级模式全局条件。
- 若某组启用 `日光`，则该组维护自己的日光阈值输入。
- `日光` 始终不参与高级模式 `level` 评分。

### 2.1 高级模式的额外约束开关
- 高级模式增加一个 `checkbox` 选项：`允许中转`。
- 当勾选 `允许中转` 时，共同中转核心候选可来自任意满足跳数约束的星区，不要求它本身命中资源组。
- 当取消勾选 `允许中转` 时，共同中转核心候选只能从“命中的资源星区”中选择。

### 3. 高级模式的候选生成规则
- 高级模式的结果单位不是单个星区，而是：
  - 一组资源星区集合
  - 一组共同中转核心候选星区集合
- 资源星区的选择顺序为：
  - 先按 `tag` 组规则判断哪些星区能命中哪些组
  - 再以中转核心星区为约束，确定哪些资源星区可以共同进入候选
- 对任意中转核心星区 `H`：
  - 某资源星区 `R` 只有在 `dist(R, H) <= N` 时才能纳入该核心对应的候选
  - 若该核心可覆盖到的资源星区集合合起来能覆盖全部 `tag` 组，则形成一个原始候选
- 若多个中转核心对应完全相同的资源星区集合，则合并为一个结果项，并将这些核心作为该结果项下的共同中转候选列表。
- 高级模式下，某个星区若同时命中多个 `tag` 组，则地图饼图需要叠加这些已命中 `tag` 组对应资源的并集切片，而不是只显示单一组资源。
- 若某星区只有 `日光` 命中，则它仍可作为过滤命中参与候选覆盖，但 `日光` 不进入评分。

### 4. 候选结果去冗余
- 最终结果保留的是资源星区集合上的“极大候选”。
- 若候选 A 的资源星区集合被候选 B 的资源星区集合严格全包含，则候选 A 不进入最终结果。
- 若两个候选的资源星区集合互不全包含，则两个候选都进入最终结果。
- 去冗余时只比较资源星区集合，不比较中转核心候选集合。
- 若两个候选资源星区集合相同但中转核心不同，则合并为一个结果项，不重复展示。

### 5. 候选排序规则
- 高级模式候选需要按分数排序。
- 对每个 `tag` 组：
  - 先在该候选的资源星区集合中，找出“命中该组最好的那个星区”
  - 再用该星区在该组内各普通资源 `tag` 的 `level` 平均值，作为该 `tag` 组的分数
- 所有 `tag` 组都得到分数后：
  - 取其中最低的那个 `tag` 组分数，作为该候选的最终分数
- `日光` 始终不参与 `level` 分数计算，只参与过滤条件判定。

### 6. 高级模式的结果展示
- 高级模式候选列表按“候选组”展示，而不是按单个星区展示。
- 每条结果至少需要表达：
  - 资源星区集合
  - 中转核心候选集合
  - 候选分数
- 地图高亮与结果列表语义保持一致：展示的是候选组，而不是单星区命中。
- 当一条结果包含多个共同中转核心候选时，这些核心应作为同一结果项的附属候选显示，而不是拆成多条重复结果。
- 候选卡片中的资源星区与中转候选都应以可点击 tag 形式展示。
- 点击候选内某个资源星区 tag 或中转候选 tag 时：
  - 若该 tag 属于非当前候选，则切换到对应候选
  - 若该 tag 属于当前候选，则保持当前候选不变
  - 两种情况下都需要触发地图 focus 到被点击的具体星区

### 7. 高级模式的组编辑与滚动交互
- 高级模式不单独设置独立编辑区；每个 `tag` 组本身就是展示与编辑容器。
- 每个 `tag` 组默认以摘要态显示当前已选 `tag` 列表与 `编辑` 按钮。
- 点击某组 `编辑` 后，该组在原位置展开并替换自身内容，而不是在组列表外额外出现编辑区。
- 同一时间只允许一个 `tag` 组处于展开编辑态。
- 每个 `tag` 组不额外显示标题；布局目标是让已选 `tag` 列表与 `编辑` 按钮尽量在一行内显示完成。
- 若 `tag` 数量过多，可在组块内部自然换行，但仍归属于该组块本身。
- 高级模式候选仍采用手动 `刷新` 触发；编辑输入变更后不自动刷新候选。
- 右侧过滤区需要提供符合页面风格的内部滚动条。
- 滚动仅发生在右侧过滤区内部，左侧地图区域不得因此额外出现滚动条。
- 点击 `刷新` 后，右侧过滤区滚动位置应保持不变，不自动跳回顶部。
- 每个组在存在多个普通资源 tag 时，必须保留 `所有项` 丰度联动下拉；该下拉可批量更新组内全部普通资源的最低丰度，并支持 `混合` 状态显示。
- 高级模式顶部控制行中，`跳数` 与 `允许中转` 必须位于同一行。
- `跳数` 输入样式必须参照简单模式中的日光输入样式，包含数字输入框与上下箭头 stepper。
- `跳数` 的可选范围固定为 `1` 到 `5`。
- 用户选中某个高级候选后，地图仍必须显示该候选资源星区的 `solid/pie` 资源饼图，不得因候选选中态而压掉资源 fill。
- 当用户切换到另一条高级候选时，上一条候选通过 tag 点击产生的资源 `selected` 状态需要被清空，避免残留单点选中态干扰新候选显示。

## 边界

### In Scope
- 地图资源过滤区的 `简单 / 高级` Tab 切换。
- 简单模式与高级模式的双组件拆分。
- 两套模式状态独立保存与切换恢复。
- 高级模式下多 `tag` 组编辑、命中计算、共同中转核心约束、候选合并与去冗余。
- 高级模式下候选结果组展示与评分排序。
- `日光` 参与过滤但不参与高级模式 `level` 评分。

### Out of Scope
- 改造地图的 sector 布局算法或跳数基础图数据来源。
- 修改简单模式现有单组过滤规则本身。
- 为高级模式引入分页、收藏、跨刷新持久化等新能力。
- 在本阶段实现运行时代码、测试代码或视觉重设计。

## 验收标准（DoD）
- 地图资源过滤区存在 `简单 / 高级` Tab，且两者使用完全不同的 Vue 组件实现。
- 在 `简单` 与 `高级` 间切换时，各自输入状态与候选结果互不覆盖，并能恢复切换前内容。
- 高级模式支持多个 `tag` 组，组内与组间均按 `AND` 语义判定。
- 同一资源星区允许同时覆盖多个 `tag` 组。
- 高级模式存在 `允许中转` checkbox；勾选时核心可来自任意星区，未勾选时核心只能从命中的资源星区中选择。
- 高级模式候选以“资源星区集合 + 中转核心候选集合”为结果单位。
- 高级模式按“资源命中先判定、再按共同中转核心 `N` 跳约束收敛”的顺序生成候选。
- 若多个核心对应相同的资源星区集合，则这些核心合并到同一结果项中展示。
- 若某结果的资源星区集合被另一结果严格全包含，则较小结果不进入最终结果。
- 若两个结果的资源星区集合互不全包含，则两个结果都进入最终结果。
- 高级模式下，某星区若命中多个 `tag` 组，地图饼图会叠加这些组对应资源的并集切片。
- 高级模式候选排序按照“每组最佳星区的组内普通资源平均 `level`，再取所有组中的最低分”为最终分数。
- `日光` 仅参与过滤，不参与高级模式候选排序分数，即使某星区只有日光命中也不例外。
- 高级模式的每个 `tag` 组默认以摘要态显示已选 `tag` 与 `编辑` 按钮，点击后在原组位置展开编辑，同一时间只允许一个组展开。
- 高级模式右侧过滤区具备自定义风格滚动条，滚动只发生在过滤区内部，地图本身不出现额外滚动条。
- 点击 `刷新` 后，右侧过滤区滚动位置保持不变。
