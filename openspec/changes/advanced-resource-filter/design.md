# advanced-resource-filter 设计说明

## 设计目标
本次设计要在不破坏现有地图资源过滤体验的前提下，增加一套“高级资源过滤”能力。
核心目标有三点：
- 用 `简单 / 高级` 双模式隔离现有单组过滤与新的组合过滤
- 在高级模式中把筛选单位从“单星区”提升为“候选组”
- 让结果生成、去冗余和排序都围绕“资源星区集合”展开，而不是围绕单一中转核心展开

## 1. 组件与状态设计

### 1.1 双模式组件边界
- 资源过滤区由外层容器负责：
  - `mode = simple | advanced`
  - Tab 切换
  - 将当前模式对应的候选高亮投递给地图
- `简单` 模式继续承载现有单组资源过滤能力。
- `高级` 模式使用独立组件，内部维护：
  - 多 `tag` 组编辑状态
  - 跳数 `N`
  - 中转核心约束计算结果
  - 候选组列表
- 双组件之间不共享内部表单状态，避免把单组逻辑强行抽象成高级逻辑的退化形式，导致状态污染和判定歧义。

### 1.2 状态保留策略
- 外层容器保留两套模式各自的状态快照。
- 切换 Tab 时仅切换可见组件和当前地图高亮来源：
  - 不重置另一模式的输入
  - 不将简单模式的资源配置强制映射为高级模式 `tag` 组
- 这样可以保证用户在简单模式和高级模式之间来回切换时，不会丢失已编辑内容。

## 2. 高级模式数据模型

### 2.1 基础输入
- `tagGroups[]`
  - 每组包含多个资源 `tag`
  - 组内 `AND`
  - 若组内包含 `日光`，则由该组维护自己的 `sunlightMinimum`
  - `日光` 只参与该组过滤，不参与评分
- `jumpLimit`
  - 共同中转核心判定所需的最大跳数 `N`
  - UI 输入范围固定为 `1..5`
- `allowTransit`
  - 对应高级模式 `允许中转` checkbox
  - `true` 时共同中转核心可来自任意星区
  - `false` 时共同中转核心只能来自命中的资源星区

### 2.2 中间计算结果
- `matchedGroupsBySector`
  - `sectorId -> groupIds[]`
  - 表示某资源星区能覆盖哪些 `tag` 组
- `matchedResourceTagsBySector`
  - `sectorId -> wareIds[]`
  - 表示某资源星区在当前候选上下文中，命中的全部组对应到的普通资源并集
- `reachableResourcesByHub`
  - `hubSectorId -> resourceSectorIds[]`
  - 表示在 `N` 跳约束下，某中转核心可接住哪些资源星区
- `coveredGroupsByHub`
  - `hubSectorId -> coveredGroupIds[]`
  - 用于判断该核心是否能形成完整候选

### 2.3 候选组结果模型
- `resourceSectorIds`
  - 该候选组的资源星区集合
- `hubCandidateSectorIds`
  - 所有能承载同一资源星区集合的共同中转核心候选
- `coveredGroupIds`
  - 该候选实际覆盖到的全部组，正常情况下应等于全部 `tag` 组
- `score`
  - 高级模式候选排序分数

## 3. 候选生成流程设计

### 3.1 先判资源命中，再判共同核心
- 第一步：计算每个资源星区命中的 `tag` 组集合。
- 第二步：根据 `allowTransit` 决定共同中转核心候选池：
  - `allowTransit = true`：可从任意星区选共同核心
  - `allowTransit = false`：只能从命中的资源星区中选共同核心
- 第三步：遍历可能的共同中转核心星区 `H`，找出所有满足 `dist(resource, H) <= N` 的资源星区。
- 第四步：判断这批资源星区合起来是否覆盖全部 `tag` 组。
- 若覆盖完整，则 `H` 生成一个原始候选。

这种流程遵循已确认规则：
- 先确定可作为资源星区的命中关系
- 再用共同中转核心约束把这些资源星区收敛成可展示的候选组

### 3.2 相同资源集合的核心合并
- 不同核心可能得到同一批资源星区。
- 这时结果应按资源星区集合归并，而不是按核心拆开。
- 例如：
  - `E -> {A,B,C,D}`
  - `F -> {A,B,C,D}`
- 最终应合并成：
  - `{A,B,C,D} + [E,F]`

这样可以避免候选列表中出现“资源完全相同，只是核心不同”的重复结果。

### 3.3 极大候选去冗余
- 原始候选合并后，需要再做一次基于资源集合的去冗余。
- 若候选 X 的 `resourceSectorIds` 是候选 Y 的严格子集，则 X 删除。
- 保留下来的都是资源集合意义上的“极大候选”。
- 这保证了最终结果既不会丢失互不全包含的有效方案，也不会保留明显被更大方案支配的冗余结果。

## 4. 评分与排序设计

### 4.1 单组分数
- 对每个 `tag` 组，在当前候选的 `resourceSectorIds` 中寻找“命中该组最好的星区”。
- “最好的星区”以该星区在该组内各普通资源 `tag` 的平均 `level` 为准。
- 即：
  - 对候选中的每个资源星区
  - 取其在该组全部普通资源 `tag` 上的 `level`
  - 计算平均值
  - 选择平均值最高的那个星区，作为该组最佳星区
- 该最高平均值就是该 `tag` 组的组分数。
- 若某星区只满足 `日光` 条件而无普通资源命中，则它仍可参与候选覆盖，但不提供分值。

### 4.2 候选最终分数
- 所有 `tag` 组各自得到组分数后：
  - 取这些组分数中的最小值
  - 作为候选的最终分数
- 该规则体现“短板优先”：
  - 只有每个 `tag` 组都不弱的候选，最终排序才靠前
- `日光` 不参与上述平均值与最终分数计算，只保留在过滤阶段作为约束，即使某星区只有日光命中也不例外。

## 5. UI 展示设计

### 5.1 简单 / 高级 Tab
- 外层资源过滤面板头部增加两个固定 Tab：
  - `简单`
  - `高级`
- Tab 切换只改变当前模式的配置区与结果区，不影响对侧模式状态。

### 5.2 高级模式编辑区
- 高级模式不单独设置外置编辑区，组列表本身就是编辑载体。
- 每个组在默认态下显示：
  - 已选 `tag` 列表
  - `编辑` 按钮
- 点击 `编辑` 后，该组原位展开并替换为编辑态内容；编辑完成后再收回摘要态。
- 同一时间仅允许一个组处于展开编辑态，避免多组同时展开造成滚动抖动和界面失焦。
- 不为组块额外绘制“组 1 / 组 2”标题栏，优先让 `tag` 列表与操作按钮共享同一行。
- 当 `tag` 数量超过可用宽度时，允许在组块内部自然换行，但不拆出额外标题区。
- 用户可以：
  - 新增 / 删除 `tag` 组
  - 在组内维护多个资源 `tag`
  - 在组内维护各普通资源的最低丰度
  - 在组内维护 `所有项` 联动丰度下拉
  - 若组内启用 `日光`，则维护该组自己的日光阈值
  - 设置共同中转跳数 `N`
  - 使用手动 `刷新` 触发候选重算
- 高级模式顶部工具行中，`跳数` 与 `允许中转` 同排显示。
- `跳数` 输入视觉应复用简单模式日光输入的数字框 + suffix + stepper 风格。

### 5.3 高级模式结果区
- 每条结果展示为一个候选组卡片，而不是单个 sector 行。
- 卡片至少需要可辨识地呈现：
  - 资源星区集合
  - 中转核心候选集合
  - 最终分数
- 当多个候选互不全包含时，结果列表需要同时保留它们。
- 候选卡片中的资源星区与中转核心候选应渲染为可点击 tag。
- 点击 tag 时的交互规则：
  - 如果点击的 tag 所属候选不是当前候选，则先切换到该候选
  - 如果点击的 tag 所属候选已经是当前候选，则不切换候选
  - 两种情况下都要向地图发送该具体星区的 focus 事件

### 5.4 地图联动
- 地图高亮来源应与当前模式一致：
  - 简单模式高亮单星区命中
  - 高级模式高亮当前选中候选组的资源星区与中转核心候选
- 高级模式的地图高亮语义必须与候选卡片一一对应，避免结果列表是“组”，地图却退回“单星区”表达。
- 高级模式的地图 fill 协议应复用现有 `SectorResourceFill` 结构：
  - `solid`
  - `pie`
- 某星区若同时命中多个 `tag` 组，则其 `pie` 切片来源于这些已命中组对应普通资源的并集。
- 若某星区只有 `日光` 命中，则它可参与过滤命中，但不应因 `日光` 进入评分。
- 用户选中高级候选后，地图仍需保持该候选资源星区的 `solid/pie` fill，不得因为单 sector 选中态覆盖资源饼图。
- 若用户通过候选内 tag 对某个资源星区做了 focus，之后切换到另一条候选时，需要先清理旧的资源 `selected` 状态，避免旧 focus 残留影响新候选的资源展示。

### 5.5 滚动容器与刷新稳定性
- 右侧资源过滤区应作为独立滚动容器。
- 滚动条样式需要与页面现有深色玻璃态/细滚动条风格保持一致，避免出现浏览器默认粗滚动条。
- 左侧地图区域不应因为右侧过滤内容过长而出现额外滚动条；地图继续保持自身缩放/拖拽语义。
- 高级模式点击 `刷新` 后：
  - 候选列表与地图高亮更新
  - 过滤区滚动位置保持不变
  - 不自动跳回顶部
- 上述行为要求高级模式将“编辑态输入状态”和“上次刷新结果状态”拆分管理。

## 6. 风险与对策

- 风险：简单模式与高级模式状态耦合后，切换 Tab 会污染已有输入。
  - 对策：双组件 + 双状态快照，明确不做状态同构。
- 风险：按核心先出结果会造成大量重复候选。
  - 对策：先生成原始候选，再按资源星区集合归并核心。
- 风险：仅按最大集合保留会误删互不全包含的有效方案。
  - 对策：采用“严格子集删除”的极大候选规则，而不是只保留单一最大项。
- 风险：评分若按总和计算，会偏向覆盖多但短板差的结果。
  - 对策：最终分数取所有组中的最低组分数，保持短板优先。
- 风险：把 `日光` 计入评分会扭曲资源质量排序。
  - 对策：明确 `日光` 只参与过滤，不参与 `level` 分数，即使某星区只有日光命中也不参与评分。
- 风险：关闭 `允许中转` 后，核心候选池和资源命中池混淆，导致结果不稳定。
  - 对策：明确先计算命中的资源星区集合，再按 `allowTransit` 切换共同核心候选池来源。
- 风险：多个组同时展开会导致右侧面板高度激增、滚动位置跳动，影响编辑稳定性。
  - 对策：限制同一时间仅允许一个组展开编辑，并采用组内原位展开替换。
- 风险：点击 `刷新` 后滚动回顶，用户丢失正在查看的位置。
  - 对策：将右侧过滤区作为独立滚动容器，并在刷新时保留 scrollTop。
