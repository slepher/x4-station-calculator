# Trade Auto Fill — 需求确认

## 目标

在存档绑定工作台的市场报价界面，按所选中转站或空间站及玩家购买/出售方向生成商品目标，减少逐项添加商品和输入数量的操作。中转站按其管理的整个星区组计算，出售使用当前有效存档中的现有库存；填充结果允许用户自由编辑。

## 已确认方案（审核重点）

### 1. 入口、站点身份与范围

1. 保留市场报价现有星区组一级菜单、玩家空间站二级菜单及买卖方向。
2. 二级菜单必须显式显示身份：中转站使用“中转站 · <星区> · <名称>”，普通站使用“空间站 · <星区> · <名称>”；保留原有星区信息，站名只出现一次。
3. 中转站身份来自当前 binding 的 tradeStation 关系，不根据名称、是否有生产模块或 option ID 前缀推断。同一实际站同时具有 stationPlan 和 tradeStation 关系时只显示一次，身份优先标为中转站。
4. 中转站汇总整个已确认星区组的玩家站点，包含中转站自身；不局限于中转站所在物理星区，不沿组间连接继续扩展。
5. 普通空间站购买只计算本站建筑需求，但使用其所在星区组普通库存抵扣；出售只使用本站库存和本站建筑留用需求。
6. 虚拟中转站可以作为组级查询入口，自身没有真实库存；虚拟普通空间站按确认规划计算建筑需求，自身库存为零。不存在的真实绑定记录不得伪装为虚拟站。

### 2. 按钮与 checkbox

1. 在左列商品搜索框上方放置“自动填充”按钮和“随选择自动填充”checkbox，显示本次方向、站点身份与计算范围。
2. 按钮始终表示按当前条件执行一次填充，与 checkbox 是否选中无关；只有上下文和必要数据完整时可用。
3. checkbox 默认关闭。由关闭改为开启时立即填充当前有效选择；若尚未选站或数据加载中，等待有效选择及完整数据后执行。
4. checkbox 开启时，切换空间站/中转站、购买/出售方向、有效存档快照后重新填充；更换星区组先清理下级站点选择，待新站选择有效后填充。
5. checkbox 关闭时，切换条件不替换现有商品，标记现有填充结果需要更新；按钮仍可主动填充。
6. checkbox 关闭操作保留已有商品。重复选中同一站点、同一方向或同一快照不构成新的填充触发。
7. 不因改数量、删商品、添加商品、搜索文字、排序、主商品、分页、报价数量或跳数变化再次填充；这不是对商品数量的持续响应式绑定。
8. checkbox 选择与目标列表在当前 binding 的应用会话内保留，离开页面再返回不重复填充或丢失手动调整；刷新应用默认关闭，不写 localStorage、IndexedDB 或 SaveBindingPlan。
9. 切换 binding 清理本次填充归属、自动模式与撤销状态，避免旧 binding 的自动行为作用于新 binding。

### 3. 填充后的手动操作

1. 每次有效填充替换整份商品列表，不追加、不累加，也不把手动数量与建议数量合并。
2. 用户可修改自动填充商品数量、移除任何商品并手动添加新商品；自动来源不锁定控件。
3. 手动操作不取消 checkbox、不立即回填、不恢复已删除商品。修改保留到下一次主动填充或 checkbox 开启时的有效条件切换。
4. 展示“已手动调整；下次切换条件将重新填充”提示（自动模式关闭时只提示已调整）；checkbox 旁说明切换站点或买卖方向会替换商品和数量。
5. 自动生成的商品使用当前游戏版本有效 ware ID，每种商品只出现一次、目标数量为正数。用户手动改为零/未填写时沿用现有市场报价的空目标规则，不再次运行自动填充。
6. 支持“撤销本次填充”，恢复替换前目标及主商品；只保存最近一次成功替换，同一交易上下文内有效。用户改目标或切换上下文后撤销入口失效，不影响 checkbox。
7. 替换后原主商品若仍在新列表中则保留，否则选择稳定顺序中的第一种商品；空列表主商品设为 null。排序模式和指标不擅自更改，继续使用现有可用性校验。

### 4. 建筑需求和库存口径

逐站、逐商品定义：
- R：本站尚待建设模块所需材料，排除已建成及已经消耗材料的施工中部分。
- B：本站所属建筑仓库实际入库材料。
- D = max(0, R - B)：仍需由普通库存或外部采购补足的本站建材数量。
- C：本站普通仓库现有库存。
- D组 = Σ D；C组 = Σ C，均在当前已确认星区组内去重汇总。

1. 建筑需求使用当前 binding 已确认建设目标及当前有效存档建设状态；排除未应用编辑草稿，同一存档待建模块和规划目标不重复相加。
2. 没有规划绑定的实际站也计入，其建筑需求由有效存档待建状态计算；未建设的新规划站保留规划需求。
3. 建筑仓库按明确所属站抵扣，抵扣后逐站截断为零；某站建筑仓库的多余材料不抵扣其他站，不作为出售库存。
4. 普通库存包含组内玩家空间站及实际中转站普通仓库，排除 NPC、建筑仓库和船舱货物；计划站与 archive 记录按实际实体去重，不按可重叠覆盖范围重复计数。
5. 未入库的 reservation 不抵扣；不以 NPC 报价 amount/desired、库存目标、未来产量或生产缓冲推荐数量替代现有库存。
6. 建材计算独立于仪表盘“已建/在建/全部”和 live/planning 展示切换；界面明细注明“仅扣已入库材料”，不沿用仪表盘扣 reservation 的 UI 计算。
7. 已确定虚拟实体的自身库存为零、完整 archive 中确实无货物记录可为零；加载失败、映射失败、未知材料和库存数据不完整必须为不可用，不能作为零继续填充。

### 5. 四种计算规则

| 所选对象与方向 | 自动商品范围 | 目标数量（逐商品） |
|---|---|---|
| 中转站购买 | 全组所有空间站的建筑材料 | max(0, D组 - C组) |
| 中转站出售 | 全组已建生产模块的主要产出商品 | max(0, C组 - D组) |
| 空间站购买 | 本站建筑材料 | max(0, D本站 - C组) |
| 空间站出售 | 本站已建生产模块的主要产出商品 | max(0, C本站 - D本站) |

1. 出售按现有库存计件，不使用“每小时净产量 × 时长”。
2. 中转站出售商品必须是组内至少一个站的主产物（resolved priority level 2），并有已建模块实际产出；单纯购入但组内不生产的囤货不自动加入。计算数量可包含该商品在组内全部普通仓库的库存。
3. 中转站与普通站主要产出均复用现有领域主产物分类（resolved priority level 2），并与当前存档已建模块产出相交；副产物、纯输入材料、尚未建成产物不自动加入。虚拟普通站没有现货可售。
4. 普通站出售只留出本站建材，不额外预留其他站建材；中转站出售统一留出全组建材。
5. 本版不额外扣生产缓冲库存、在途订单或预订，不根据运输船容量或可成交 NPC 数量截断目标。
6. 自动填充只产生查询目标，不实际预留库存、搬运材料或下交易指令。多次独立查询可能抵扣同一组库存，不表示可同时执行的采购计划。

### 6. 结果、明细和异常

1. 有效非空结果写入商品目标并更新现有 NPC 报价查询，生成“自动”来源和逐商品计算明细；手动编辑标为已调整。
2. 有效空结果同样替换为空，购买提示“建筑材料已满足”，出售提示“没有可出售盈余”；不得保留上一座站的结果伪装成本次商品。
3. 无效上下文或必要数据不可用时不修改列表，显示具体原因并标记结果未更新。数据完整后只执行仍属于当前选择的待处理触发。
4. 明细显示需求、建筑仓库已入库、尚需建材、普通库存、最终建议；组级结果可展开逐站库存和建材，说明库存分布在组内各站，并非都位于中转站。
5. 即使 NPC 无匹配报价，仍保留有效的填充目标；NPC 候选和船只载量继续使用现有行为。
6. 快速切换选择或存档时旧计算结果不得覆盖最新上下文；手动调整后普通渲染、数据派生更新或页面重挂载不得触发覆盖。 请求等待数据期间若用户手动编辑目标，该先前待处理请求失效，checkbox 保持原状态。

### 7. 技术约束

严格采用 store -> presenter -> vue，不新增 adapter、view model 或 facade。领域层负责身份、组成员、需求、库存和计算结果；presenter 负责展示、事件与状态提示；Vue 只消费 presenter。不修改存档 parser、Rust/WASM 或持久化 schema。中英文文案及稳定 testid 同步维护。

## 边界

### In Scope
- 市场报价按钮、checkbox、站点身份标签及去重。
- 四种填充规则、计算明细、空结果及不可用状态。
- 自由手动编辑、有限撤销、会话内自动模式与最新上下文保护。
- 随实现任务完成的 focused Unit 覆盖，以及实现结束后的 npm run build。

### Out of Scope
- 自动交易、船只分配、实际调拨和跨查询库存预留。
- 生产时长模式、额外生产缓冲扣除、船舱或 NPC 库存计入。
- 跨星区组连接汇总、parser 改造、持久化设置迁移。
- 本阶段源码或运行测试修改；E2E 文档及执行走独立 x4-e2e-test 工作流。

## 验收标准（DoD）

1. 同一真实中转站只出现一次并标记“中转站”，普通站标记“空间站”，组内及未绑定实际站范围保持正确。
2. 四种公式按有效存档库存和确认建设目标得到正确正数，本站/组级范围不同且不重复抵扣。
3. 某站建筑仓库超额不抵其他站；已建/施工已耗材料、在途 reservation 和未来产量不重复计入。
4. checkbox 默认关闭，勾选立即填充，开启后的站点/方向/有效快照切换按最新条件只应用一次，关闭不清空。
5. 按钮在 checkbox 两种状态均能主动重新填充；重复填充不累加。
6. 自动商品可删、可改数量、可手动增添；checkbox 不改变，不即时恢复或覆盖，直到下一次合法触发。
7. 有效空结果清空列表与主商品；不可用结果保留列表但标记未更新，异步旧结果不能覆盖当前选择。
8. 离开返回保留会话选择和手动调整，不触发新填充；切换 binding 隔离自动状态与归属。
9. 撤销仅恢复同上下文最后一次填充前目标及主商品，编辑或切换上下文后失效。
10. 计算明细能解释最终数量，无报价不删目标，不用船舱容量截断，原排序及数量校验继续生效。
11. store -> presenter -> vue 检查通过，各行为任务包含 focused Unit；实现完成后 npm run build 通过或报告明确阻塞。

## 未决项

无。

## 商品列表布局补充（用户确认）

商品使用两行卡片：第一行完整商品名与移除按钮，第二行来源标记与右对齐数量输入。名称允许换行，不使用省略号；不显示“目标数量”说明，保留读屏标签。
