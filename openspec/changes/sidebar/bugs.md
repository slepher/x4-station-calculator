# Sidebar implementation bugs

## SIDEBAR-010 — 展开／收起图标偏移及顶部按钮边距不同

- 用户反馈：切换展开／收起时图标抖动，顶部展开图标与其他图标的左边距不一致。
- 源码复现：展开导航使用左侧 padding，窄栏改为居中，站点拖拽手柄占据布局宽度；分组标题在展开和窄栏分别为一行／两行，导致成员纵向位置变化。
- 修复目标：所有状态使用固定主图标列和行高，顶部按钮同轴，手柄不参与布局，分组标题保持一行并保留独立导航区域。
- 实现：统一 32px 主图标中心线和 36px 行高，移除窄栏独有的居中／边距规则；拖拽手柄绝对定位，分组标题保持一行。
- 本轮证据：26 项 focused Unit 通过，最终构建通过；布局样式不以 jsdom 冒充真实视觉证据。
- 状态：Confirmed（用户反馈及现有 CSS）；实现已调整，真实几何仍需浏览器验收。
- 后续用户反馈（20:29）：5174 页面刷新后图标偏移已修正；仍补充浏览器坐标证据，先前截图不能直接判定最新样式失败。

## SIDEBAR-009 — 自行加入上下分区和百分比高度限制

- 用户确认：移除上下分区、横向分割线与 `55%` 高度上限；顶部展开／收起按钮固定，蓝图“＋”始终位于最底部，其他内容统一滚动。
- 根因：功能区、站点区分别使用滚动容器；顶部按钮随功能区滚动，功能区与底部设置百分比高度上限，并增加横向分割线。
- 修复目标：唯一中间滚动容器，顶部按钮和蓝图底部动作位于容器外且不收缩；保留业务分组折叠与成员竖线。
- 本轮证据：20:17 组件新增两用例失败，确认顶部按钮仍位于功能区容器；20:21 组件／presenter 共 26 tests passed，最终构建通过。
- 状态：Fixed（focused Unit 容器与行为合同）；浏览器位置与滚动验收交 `/x4:verify sidebar`。

## SIDEBAR-006 — 收起栏顶部按钮与导航图标未对齐、折叠提示不清晰

- 用户复现：截图中顶部双箭头偏左，功能图标居中；反馈折叠没有展示。
- 根因：顶部按钮固定左边距，导航按钮独立居中；分组箭头参与布局，也使组标识偏右。折叠控制使用文本字形。
- 修复：统一窄栏图标中心线；参照用户 Chrome 截图使用彩色圆角 SVG 箭头与展开成员竖线；地形改造树增加独立折叠控制，保留导航／菜单点击区域。
- 回归边界：Unit 检查折叠控制两种状态与点击合同；最终实际几何仍交浏览器验收。
- 当前运行证据：20:00 组件测试缺少 SVG 失败；20:04 树折叠测试缺少独立按钮失败；20:10 同一组件文件及 presenter／domain 共 30 tests passed。
- 状态：Confirmed（用户截图）；实现已调整、DOM 合同通过，实际视觉等待浏览器验收。

## SIDEBAR-008 — 可选布尔 prop 将普通站点误判为可折叠树

- 发现阶段：本轮 focused Unit，`retains clickable live entries` 失败。
- 根因：Vue 将未传入的可选 Boolean prop 默认为 false，不能用 undefined 表示“没有子树”。
- 修复：明确 null 为普通行，true／false 为树展开／收起。
- 回归：20:10 同一组件文件及 presenter／domain 共 30 tests passed，普通站点仍可导航，树按钮独立折叠。
- 状态：Fixed（focused Unit），最终验证交 `/x4:verify sidebar`。

## SIDEBAR-001 — 切换绑定身份后未初始化偏好

- 发现阶段：`/x4:apply sidebar` focused Unit。
- 复现：绑定 A 中设置折叠和滚动，切到绑定 B；B 的上下文偏好未建立。
- 根因：实体同步 watcher 只观察 loaded、站点和分组，未观察 contextId；实体列表相同的身份切换未触发同步。
- 修复：将 contextId 纳入同步依赖。
- 回归：`tests/unit/sidebar/sidebar-presenter.spec.ts` 的恢复与身份切换用例。
- 状态：实现层已修复；最终验证交 `/x4:verify sidebar`。

## SIDEBAR-002 — 数据切换加载中可能提前清理偏好

- 发现阶段：检查 live store 加载生命周期。
- 根因：isReady 只覆盖初始化，切换绑定／archive 的异步站点读取期间仍可为 true。
- 修复：领域 store 提供 loadedBindingGameGuid，读取开始清空，成功且上下文仍有效才设置；presenter 在该标识与当前绑定一致时才清理偏好。
- 回归：侧栏加载前保留／加载后清理与旧上下文读取用例。
- 状态：实现层已修复；最终验证交 `/x4:verify sidebar`。

## SIDEBAR-003 — 加载完成前恢复滚动会被空列表覆盖

- 发现阶段：最终恢复流程检查。
- 根因：上下文 watcher 挂载时立刻恢复滚动，而异步实体尚未到达；浏览器空列表可能将 scrollTop 裁为 0 并写回偏好。
- 修复：加载完成后才发送恢复指令；加载中忽略滚动写入并隐藏未就绪站点。
- 回归：`sidebar-presenter.spec.ts` 的加载前滚动保护与加载后恢复用例。
- 状态：实现层已修复；最终验证交 `/x4:verify sidebar`。

## SIDEBAR-004 — 取消处理不应增加全局键盘快捷键

- 发现阶段：request/design 边界审查。

- 修复：移除全局键盘监听；取消通过 pointercancel、touchcancel、窗口 blur、外部释放和卸载处理。
- 回归：`sidebar-component.spec.ts` 的取消与监听完整清理用例。
- 状态：实现层已修复；最终验证交 `/x4:verify sidebar`。
