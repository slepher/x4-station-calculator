# terraforming-blocks Request

## 目标

收敛 terraforming 任务树与任务队列中的 stat 方块展示，解决同一 stat 的条件与效果分层重复问题。将任务树中的同 stat 条件与效果合并为同一条方块图表达，并让任务队列中所有可映射为 stat ranges 的前后变化统一改为单行效果方块图。

## 已确认方案（审核重点）

### 任务树：同 stat 条件与效果合并

- 任务树中不再把同一 stat 分别显示在 `condition-list` 和 `effect-list` 两处。
- 若某个项目同时包含某 stat 的条件与效果，必须合并成同一条 stat 行。
- 合并后的方块图继续沿用完整 value 色带：
  - 每个方块对应一个真实 integer value，而不是一个 state
  - `value = 0` 跳过，不显示
  - `value <= currentValue` 的方块为实心
  - `value > currentValue` 的方块为空心
  - 方块颜色来自对应 range 的 `rgb`
- 合并后的基础句法固定为：
  - 有 ranges 的 stat：`[stat名  方块图  效果文案]`
  - 无 ranges 的 stat：`[stat名  数值变化/需求文本]`
- 同 stat 行中：
  - `strip` 沿用当前完整 value 色带方案
  - 效果文案前移到方块图之前，形成 `stat名 + 变化值 + 方块图` 的阅读顺序
  - `stat名`、变化值、方块图三者之间的横向间距扩大到原先的约 1.5 倍
  - 条件命中区继续沿用当前 `condition-segment` 外框语义，外框覆盖在方块图上方
  - 效果变化直接叠加在同一条方块图中，不再单独再画一条效果 strip
  - 已执行过的一次性项目，对 `ranges` 型 stat 不再显示效果预览目标
  - 已执行过的一次性项目，对数字型 stat 仍显示执行结果文本

### 任务树：三种场景统一句法

- 仅存在条件：
  - 显示 `stat名 + 方块图 + 条件外框`
  - 不显示效果文案
- 仅存在效果：
  - 显示 `stat名 + 方块图 + 效果叠加 + 效果文案`
  - 不显示条件外框
- 条件与效果同时存在：
  - 显示 `stat名 + 方块图 + 条件外框 + 效果叠加 + 效果文案`
  - 不允许拆分成上下两条重复 stat 行

### 方块视觉语义

- `condition.min/max` 按 state 语义解释
- `condition.minvalue/maxvalue` 按真实 value 语义解释
- 条件命中区若覆盖多个连续 value，必须合并为连续外框
- `increase` 使用空心目标格 + 内部 1/2 实心小方块表示
- `increase` 的内部 1/2 小方块颜色必须与该格自身 `rgb` 一致
- `decrease` 使用“当前实心格内部打孔”的语义
- `decrease` 的孔洞边框颜色必须与该格自身 `rgb` 一致
- `decrease` 的孔洞填充色必须是背景色，不得使用会透出底层颜色的半透明 rgba

### 数字型 stat

- 无 `ranges` 的 stat 不画方块。
- 若同时存在效果与条件，统一压成单行文本：
  - 例如：`人口 120,000 -> 140,000 需要 >= 150,000`
- 若只有条件，则显示 `当前值 + 需求文本`
- 若只有效果，则显示 `before -> after`

### 任务队列：效果方块图统一

- 右列任务队列也改为单行表达。
- 凡是能映射到 terraforming stat ranges 的变化，都必须显示为单行效果方块图。
- 队列中的方块图不显示条件外框，因为任务队列只回答“这一条执行改了什么”，不承担可用性判断。
- 队列中的方块图不显示效果文案，如 `+2(max:5)`、`-2(min:3)`，避免与任务树重复。
- 队列中的数字型 stat 继续使用单行数值变化：
  - 例如：`人口 120,000 -> 140,000`

### 非 stat 条目保持独立

- 项目前置依赖仍保留在任务树条件区，不并入 stat 方块行。
- rebate、sideEffect、description 等非 stat 效果仍保留独立条目，不强行映射到方块图。
- 本次变更只处理“可映射到同一 stat”的条件与效果合并，不扩展到其他 effect 类型。

## 边界

### In Scope

- 任务树中同 stat 条件与效果的单条合并展示
- 任务树中有 ranges / 无 ranges stat 的统一句法
- 任务队列中可方块化 stat 变化的单行效果方块图
- Presenter 层按 `statId` 聚合条件与效果，向 Vue 输出单条 stat line 模型
- `TerraformingStatScale` 或其等价单一基础组件扩展，以支持“条件外框 + 效果叠加”同图表达

### Out of Scope

- 新增回退预览三态展示
- rebate / sideEffect / description 的图形化
- 运行时规则或可用性判定语义变更
- 测试编写与测试执行

## 验收标准（DoD）

1. 任务树中，同一项目若对同一 stat 同时存在条件与效果，只显示一条合并后的 stat 行
2. 合并后的 stat 行继续使用完整 value 色带，条件外框覆盖在方块图上方，效果变化叠加在同一条方块图中
3. 任务树中，只有条件、只有效果、条件+效果同时存在三种场景均使用同一条 stat 行句法，不再重复输出两条同 stat 信息
4. 无 `ranges` 的 stat 使用单行文本表达，不显示方块
5. 右列任务队列中，凡是可映射到 stat ranges 的变化，都改为单行效果方块图
6. 右列任务队列中，不显示条件外框，不显示 `+2(max:5)` / `-2(min:3)` 这类效果文案
7. 右列任务队列中的数字型 stat 继续显示为单行数值变化文本
8. 已执行过的一次性项目中，`ranges` 型 stat 不再显示效果预览目标，但数字型 stat 仍显示执行结果文本
9. 任务树中的 `ranges` 型 stat 行按 `stat名 + 变化值 + 方块图` 顺序排布，名称、变化值、方块图之间的横向间距扩大
