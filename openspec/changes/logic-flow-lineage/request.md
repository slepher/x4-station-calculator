# 逻辑组网：物理模块隔离与血统导向机制需求 (Lineage Request)

## 1. 核心架构与主键逻辑

### 1.1 节点身份 (Node Identity)
- **唯一主键 (Primary Key)**: `moduleId` (物理模块宏 ID，如 `prod_tel_hullparts_macro`)。
- **原则**: 规划组内 `moduleId` 唯一。物理模块不同即视为不同节点，实现天然隔离。
- **血统元数据 (Lineage)**: 节点保存 `lineage` 属性（如 `industrial_terran`, `agri_argon`），记录其来源体系。

### 1.2 血统的作用 (Lineage Role)
- **回溯导航**: 仅在节点执行上游回溯时，作为 `findModuleForWare(wareId, race)` 的 `race` 参数。
- **遗传性**: 即使是通用模块（如武器部件），其派生的上游节点也会继承父节点的血统，优先寻找种族专属模块。

### 1.3 T0 资源特殊处理 (Tier 0 Behavior)
- **无血统性**: 矿石、硅、气体、能量电池等基础资源不区分种族体系。
- **强制合并**: 规划组内所有来源的 T0 需求始终合并为同一个资源节点，不保存血统信息。

## 2. 锁定机制 (Locking Mechanism)

### 2.1 候选区锁定 (Candidate Zone Lock)
- **UI 表现**: 候选区二级菜单栏增加 **iOS 风格滑块 (Toggle Switch)**。
- **功能**: 
  - 决定新创建规划组的默认锁定状态。
  - 滑块旁显示当前体系名称（如 `Terran-Agri`）。

### 2.2 规划组锁定 (Planning Group Lock)
- **UI 表现**: 组标题栏使用 **iOS 风格滑块**，滑块旁显示锁定的血统名称。
- **准入检查 (Toggle Permission)**: 
  - 仅当组内所有**手动添加 (Manual)** 的模块血统一致时，允许自由切换锁定状态。
  - 如果手动模块血统不一，滑块置灰禁用，防止物理模块冲突。
- **锁定状态 (Locked)**:
  - **强行同化**: 任何拖入或派生的资源，强制通过锁定血统重映射 `moduleId`。
  - **直接禁止 (Strict Rejection)**: 如果拖入资源不在锁定体系的回溯表内，禁止拖入并显示 🚫 标识。
- **未锁定状态 (Unlocked)**:
  - **尊重来源**: 节点保留拖出时的原始血统。
  - **多体系并存**: 允许不同 `moduleId` 的节点并存。

## 3. 交互与行为细化

### 3.1 节点操作增强 (Node Operations)
- **Auto 节点“转正”**: 自动生成的节点（虚线）在删除按钮相同位置显示一个 **➕ (添加)** 按钮，点击后转为 Manual 节点（实线）。
- **Manual 节点“降级”**: 手动节点显示 **🗑️ (删除)** 按钮，点击后根据依赖情况降级为 Auto 或直接删除。

### 3.2 快速添加菜单增强 (Quick Add Menu)
- **状态感知**: 菜单中每个规划组名称后增加状态后缀（如 `(Locked)`, `(Duplicated)`）。
- **交互拦截**: 处于 `Locked`（产物不匹配）或 `Duplicated` 状态的组项置灰不可点击，与拖拽拦截逻辑保持一致。

### 3.3 i18n 术语重构
- **冲突处理**: 由于“锁定”一词将用于规划组体系约束，原 `FlowNode` 上的“锁定/解锁”功能（转外部供应）需重命名。
- **选定方案**: **隔离 (Isolate / Connect)**
  - **Isolate (隔离)**: 将该节点在逻辑上与上游隔离，成为一个独立的供应源（实线）。
  - **Connect (连接)**: 重新连接上游逻辑，使其作为整个产业链条的一环（虚线）。

### 3.4 其他
- **删除隔离**: 基于 `moduleId` 删除。删除特定模块节点仅影响其专属上游链条。
- **资源合并**: T0 资源无血统，始终合并。
