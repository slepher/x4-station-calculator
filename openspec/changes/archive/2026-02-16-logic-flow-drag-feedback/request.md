# 规划区拖拽反馈增强需求 (Request)

## 核心目标
提升规划区在模块拖拽过程中的视觉反馈质量，让用户能够直观地预判操作结果，并清晰感知产业链的资源消耗情况。

## 详细需求描述

### 1. 新产线创建的“所见即所得”
目前将模块拖拽到“新建产线”区域时缺乏即时反馈。
- **动态占位**：当模块悬停在新建区域时，该区域应立即“幻化”成一条正式产线的样子，显示预期的产线名称，并在网格中展示该模块的落点位置。
- **状态回滚**：如果用户将模块移开或取消拖拽，该区域应恢复为初始的“添加”状态，不留下任何残留。
- **静态资源预览集成**：移除原有的悬浮资源预览组件，将资源预览直接集成到“新建产线”的 Header 区域。

### 2. 紧凑模式下的基础资源预览
在紧凑视图中，用户需要快速了解各产线的资源压力。
- **实时资源看板**：在产线组的标题栏位置，实时展示该产线消耗的所有基础资源（Tier 0，如矿石、硅等），但不包含能量电池。
- **悬停预测与回滚**：当拖拽模块悬停在某条产线上时，资源看板应立即更新，展示加入该模块后总共需要的资源情况。一旦鼠标移出该产线或取消拖拽，资源看板必须立即回滚到该产线原始的资源状态。
- **新增高亮**：如果加入新模块导致产线产生了原本不需要的新资源，这些新增的资源图标应通过视觉特效（如高亮、动画等）显著标出。

### 3. Dependency-Follow Sorting (依赖跟随排序)
Header 中的 T0 资源列表展示逻辑重构，不再使用简单的字母排序。
- **产物顺序优先**：T0 资源的排列顺序必须严格跟随产物（Manual Node）的排列顺序（Tier 高 -> 低）。即：排在前面的产物，其所需的 T0 资源也应排在前面。
- **去重逻辑**：如果多个产物都需要同一种 T0 资源，仅保留该资源在列表中第一次出现的位置（First Occurrence），避免重复展示。

### 4. 视觉精简与 i18n
为了适应紧凑模式的空间限制，进行以下视觉优化：
- **移除悬浮组件**：彻底移除跟随鼠标的 `DraggingResourcePreview` 悬浮组件，避免遮挡视线。
- **i18n 文本化**：资源展示不再使用图标，而是使用 i18n 定义的短文本（如 `Si`, `Ore`），以节省空间并保持风格统一。

### 5. 候选区资源预览 (Candidate Zone Enhancement)
在候选区的每个产物卡片中，**总是**在产物名称右侧显示该产物所需的 T0 资源。
- **展示逻辑**：直接展示该产物所需的 T0 资源列表，排除能量电池。
- **视觉风格**：与规划区拖拽状态下的资源预览保持一致（缩写名片形式 `Si`, `Ore` 等），使用 i18n 短文本。
- **位置**：位于产物名称（Name）的右侧，紧随其后。

### 6. T0 Ware Behavior (T0 产物行为)
- **禁止拖拽**：候选区中的 Tier 0 产物（原材料）不可被拖拽。
- **隐藏资源预览**：Tier 0 产物不显示 T0 资源需求预览（因为它们本身就是基础资源）。

### 7. 候选区快速添加按钮 (Candidate Zone Quick Add)
- **T0 资源按钮隐藏**：为了减少误操作和视觉干扰，候选区中的 T0 资源（矿物、气体等）不应显示 "+"（快速添加）按钮。
- **例外**：`Energy Cells`（能量电池）作为通用的 T0 资源，仍然保留 "+" 按钮。
- **菜单交互**：当点击 "+" 按钮打开菜单并选择 "New Production Line" 后，该菜单应自动关闭（Dismiss），不应残留在界面上。

### 8. 锁定节点逻辑隔离 (Lock Logic Isolation)
- **规划状态隔离**：被标记为“锁定”（Locked）的节点，不应计入候选区的“已规划”（绿色圆点）状态判断中。即：如果一个资源只存在于锁定节点中，候选区对应的卡片不应显示绿点。
- **自动扩展隔离**：当拖拽新的生产线（包含依赖）到规划区时，如果依赖链中涉及已锁定的资源节点：
  - 不应修改该锁定节点的属性（如从 Manual 变 Auto）。
  - 不应生成新的生产线来覆盖或重复该锁定节点。
  - 自动扩展应在遇到锁定节点时停止递归。

### 9. 锁定覆盖与交互解锁 (Lock Override & Drag Unlock)
- **拖拽反馈增强**：当拖拽一个产物悬停在已包含该产物“锁定节点”的规划组上时：
  - **初始反馈**：显示 `Locked` 标签（而非 `Duplicated`）。
  - **激活反馈**：当鼠标进一步悬停在规划组网格区域时，标签变为 `Unlock`，表示放下鼠标将执行解锁操作。
  - **停靠预览**：即使该节点已锁定，拖拽到网格区域时，也应在对应位置显示预览停靠点（Phantom Node），指示接管位置。
- **解锁行为**：投放后，该现有的锁定节点应被解锁（`isLocked: false`），并自动触发上游依赖的生成（`expandUpstream`），从而生成对应的产线。

### 12. 节点权限矩阵与交互逻辑 (Node Permission Matrix)
根据节点来源和依赖关系，严格限制操作按钮的显示和行为：
- **纯手工节点** (Manual Only)：
  - **定义**：用户手动拖入，且不被当前组内任何其他节点依赖。
  - **权限**：仅显示 **删除 (🗑️)** 按钮，禁止锁定。
  - **行为**：点击删除直接移除节点。
- **纯自动节点** (Auto Only)：
  - **定义**：系统自动生成，且用户从未手动干预（没有手动身份）。
  - **权限**：仅显示 **锁定 (🔒)** 按钮，禁止直接删除。
  - **行为**：点击锁定将其转为外部供应，停止上游递归。
- **混合身份节点** (Manual + Auto/Dependency)：
  - **定义**：用户手动拖入，同时也被其他节点作为依赖。
  - **权限**：同时显示 **删除 (🗑️)** 和 **锁定 (🔒)** 按钮。
  - **行为 - 点击删除**：执行“降级”操作，去除其手动身份，使其变回纯自动节点（保留在组内以满足依赖）。
  - **行为 - 点击锁定**：执行“先删后锁”逻辑，先去除手动身份，再将其转为锁定状态（转为外部供应）。

### 10. 节点来源视觉区分 (Node Provenance Visualization)
- **区分度设计**：规划区内的节点需要根据其生成来源进行视觉区分。
- **Manual Node**：用户手动拖拽或通过 "+" 按钮创建的节点，使用实线边框，视觉层级最高。
- **Auto Node**：由系统根据依赖自动生成的节点，使用虚线边框或微调透明度，并可能增加一个微小的标识。

### 13. Auto 节点“转正”交互 (Auto Node Promotion)
当拖拽一个产物到已经包含该产物“Auto 节点”（由依赖生成的虚线节点）的规划组上时：
- **不再提示重复**：不再显示 `Duplicated` 标签，也不再拦截投放。
- **动态反馈**：
  - **Header 状态**：显示 `Auto` 标签，提示该节点当前已作为依赖存在。
  - **Grid 状态**：当鼠标移入网格区域时，标签变为 `Manual`，表示投放后将转为手动控制。
  - **停靠预览**：在 Grid 区域对应的 Auto 节点位置显示预览停靠点（Phantom Node）。
- **转正行为**：投放后，该 Auto 节点的 `source` 变为 `manual`，边框变为实线。
- **逻辑意义**：用户通过该操作获得了对该节点的显式管理权（如删除权），同时保留其作为下游依赖的功能（进入 Hybrid 状态）。

### 11. 移除手动扩展按钮 (Removal of Manual Expand)
- **背景**：由于系统已在各交互环节（添加、解锁、拖拽）实现了全自动的上游扩展。
- **需求**：移除节点（FlowNode）上用于手动触发扩展的 🌳 (Expand) 按钮。
- **交互简化**：减少 UI 噪音，强化“自动化”这一核心产品心智。

### 14. 候选区 T0 资源推导化 (Candidate Zone T0 Derivation)
- **核心逻辑变更**：候选区显示的 T0 资源（矿石、硅、气体等）不再基于硬编码的白名单组生成，而是完全基于当前种族生产线的推导结果。
- **动态过滤**：
  - **按需显示**：只有当当前二级分类（如 Terran, Default）下的生产模块确实需要某种 T0 资源时，该资源才会出现在候选区。
  - **自动去杂质**：不再需要手动排除 N 矿 (Nividium) 或 原始废料 (Raw Scrap)，如果没有任何模块消耗它们，它们将自动从界面消失。
  - **种族差异**：例如，在 Terran 分类下，由于生产线不消耗硅，硅将自动不显示。
  - **回溯逻辑重构 (分类隔离)**：
    - **职责转移**：回溯逻辑完全由 DataStore 负责，UI 层不再进行 `group` 过滤。
    - **双重隔离种子**：
      - **工业回溯表**：仅从工业组模块（矿石、气体、高科技等）中提取种子。
      - **农业回溯表**：仅从农业组模块（食品、医药、农产品等）中提取种子。
    - **T0 精准化**：由于种子被分类隔离，T0 资源将仅在被相应分类的生产线触达时才出现。例如：Terran 农业回溯触达甲烷，不触达硅；Terran 工业回溯触达硅，不触达甲烷。
    - **性能优化**：继续保留 `modulesByOutputMap` 索引以保证 $O(1)$ 的查找效率。
- **Store 预计算**：该推导逻辑应在 `useGameDataStore` 的预处理阶段完成，UI 仅作为展示层读取计算好的结果。
- **能量电池**：作为基础能源，它会因为被生产模块产出或消耗而自然出现在推导结果中。

---
**注意**：所有资源预览逻辑均需排除能量电池，以保持界面的简洁，聚焦于关键矿物资源。
