## Unit Tests

- [x] UT-1: isDirty 计算属性
  - **目标**: 验证脏检查逻辑正确性
  - **步骤**:
    1. 创建新的 Store 实例
    2. 验证初始状态 isDirty 为 false
    3. 修改 groups 数据（添加新产线组）
    4. 验证 isDirty 变为 true
    5. 调用 saveCurrentPlan
    6. 验证 isDirty 变为 false
    7. 修改 settings 数据
    8. 验证 isDirty 变为 true
  - **期待结果**: isDirty 正确反映方案修改状态

- [x] UT-2: saveCurrentPlan 方法
  - **目标**: 验证方案保存逻辑
  - **步骤**:
    1. 创建包含 manual 和 isolated 节点的产线组
    2. 调用 saveCurrentPlan
    3. 验证 savedPlans.list 中新增了方案
    4. 验证 auto 节点未被保存到方案数据中
    5. 验证 lastUpdated 时间戳正确
    6. 验证 lastSavedSnapshot 更新
  - **期待结果**: 方案正确保存，仅包含 manual 和 isolated 节点

- [x] UT-3: loadPlan 方法
  - **目标**: 验证方案加载和 auto 节点重建逻辑
  - **步骤**:
    1. 准备一个包含 manual 节点的 SavedFlowPlan
    2. 调用 loadPlan
    3. 验证 groups 正确恢复
    4. 验证 auto 节点通过 expandUpstream 正确重建
    5. 验证 currentPlanName 正确设置
    6. 验证 activeGroupId 正确设置
    7. 验证 lastSavedSnapshot 更新
  - **期待结果**: 方案正确加载，auto 节点正确重建

- [x] UT-4: clearAll 方法
  - **目标**: 验证清空逻辑
  - **步骤**:
    1. 创建包含多个产线组的状态
    2. 设置 currentPlanName
    3. 调用 clearAll
    4. 验证 groups 为空数组
    5. 验证 currentPlanName 为空
    6. 验证 activeGroupId 为 null
    7. 验证 savedPlans.activeId 为 null
  - **期待结果**: 所有状态正确重置

- [x] UT-5: settings 作为方案的一部分保存和加载
  - **目标**: 验证设置随方案一起保存和加载
  - **步骤**:
    1. 创建一个方案，设置 isDefaultLocked 为 true
    2. 保存方案
    3. 验证方案数据中包含 settings 字段
    4. 修改 isDefaultLocked 为 false
    5. 保存方案
    6. 加载该方案
    7. 验证 settings.isDefaultLocked 正确恢复为 false
  - **期待结果**: 设置作为方案的一部分正确保存和恢复

- [x] UT-6: deletePlan 方法
  - **目标**: 验证删除方案逻辑
  - **步骤**:
    1. 创建多个保存的方案
    2. 调用 deletePlan 删除中间的方案
    3. 验证方案从列表中移除
    4. 验证其他方案不受影响
    5. 如果删除的是当前活动方案，验证 activeId 重置
  - **期待结果**: 方案正确删除，状态正确更新

- [x] UT-7: applyPlan 方法 - isolated 节点处理顺序
  - **目标**: 验证 isolated 节点在 manual 节点之前被添加，确保 expandUpstream 能正确跳过它们
  - **步骤**:
    1. 准备包含 isolated 节点和 manual 节点的 SavedFlowPlan
    2. 调用 applyPlan
    3. 验证 isolated 节点正确恢复
    4. 验证 isolated 节点的 isIsolated 为 true
    5. 验证 isolated 节点没有 moduleId
    6. 验证 expandUpstream 正确跳过了 isolated 节点（没有为它们创建上游）
  - **期待结果**: isolated 节点正确恢复，expandUpstream 正确跳过它们

- [x] UT-9: 空方案保存验证
  - **目标**: 验证空方案无法保存
  - **步骤**:
    1. 创建空的 Store 状态（groups 为空）
    2. 调用 saveCurrentPlan
    3. 验证返回 false 或抛出错误
    4. 验证 savedPlans.list 未增加
  - **期待结果**: 空方案无法保存
