## Context

当前逻辑组网（Logic Flow）依赖简单的 `wareId` 匹配，这导致了严重的种族体系冲突。例如，用户在规划泰拉迪（Teladi）产线时，系统会自动合并通用的（Default）船体部件模块，导致整条产线退化为通用工业，无法维持泰拉迪特色的“T材料”供应链。

## Goals / Non-Goals

**Goals:**
- 实现物理模块（Module ID）级别的产线隔离。
- 实现基于血统（Lineage）的递归回溯导航。
- 实现规划组级别的体系锁定约束（iOS 风格滑块）。
- 提升 Auto 节点的管理权转移体验（转正按钮）。
- 规范化节点操作术语（Isolate/Connect）。

**Non-Goals:**
- 不对现有的资源计算引擎（Buffer Calculation）进行重大重构。
- 不支持 T0 资源（矿石、能量电池等）的种族隔离（维持全宇宙通用）。
- 不支持跨规划组的产线自动合并。

## Decisions

### 1. 节点主键与隔离策略
- **Decision**: 维持 `moduleId` 作为物理层面的唯一标识，通过引入 `lineage` 元数据来隔离逻辑路径。
- **Rationale**: 物理模块是生产力的真实载体。如果两个路径使用了不同的 `moduleId`，它们天然就是隔离的。如果使用了相同的 `moduleId`，它们在物理上是一体的，但通过 `lineage` 我们可以控制它们回溯的方向。
- **Alternative**: 将 `(moduleId, lineage)` 作为复合主键。被否决，因为这会导致物理上的同一个模块在 UI 上出现多次，造成冗余感。

### 2. 体系锁定 (System Locking) 交互
- **Decision**: 采用 iOS 风格滑块（Toggle Switch）置于规划组 Header。
- **Rationale**: 滑块具有明确的状态感，且比简单的开关图标更具视觉吸引力。配合文字标签（如 `Terran-Agri`），能清晰传达当前的“生产标准”。
- **Alternative**: 下拉菜单选择。被否决，因为切换频次较低且通常是二元状态（锁定当前体系 vs 不限）。

### 3. 术语重构 (Isolate / Connect)
- **Decision**: 将节点原有的 Lock/Unlock 重命名为 Isolate/Connect。
- **Rationale**: 规划组层面的“锁定”占据了最强的语义位。节点层面的“断开与上游连接”更符合“隔离”的逻辑含义。

### 4. T0 资源自动合并与约束
- **Decision**: T0 资源（Tier 0）在规划组内始终合并，且**剥夺其手动管理权**。
- **Rationale**: T0 资源（如矿石）没有生产模块，不具备血统属性。合并显示能降低复杂度。同时，限制其不能被“转正”和“手动添加”，确保它们始终作为“按需生成”的末端节点存在。

### 5. 隔离前提与强制清理 (Isolation & Forced Cleanup)
- **Decision**: 隔离功能必须基于“下游需求”存在，且节点存留必须严格绑定“下游需求”。
- **Rationale**: 
  - **隔离前提**: 无下游消费的节点隔离没有逻辑意义，因此 UI 上需隐藏操作。
  - **强制清理**: 为了防止 UI 堆积无用的“僵尸节点”（尤其是已隔离但已无下游需求的节点），系统应在任何下游变更时执行彻底的清理。即使是处于 Isolate 状态的节点，一旦失去下游依赖，也应被删除。

## Risks / Trade-offs

- **[Risk]** 锁定切换导致数据不兼容 → **[Mitigation]** 在切换锁定前进行“血统一致性”检查，如果不一致则禁用切换。
- **[Risk]** 模块重映射失败（目标体系无对应模块） → **[Mitigation]** 当目标体系无模块时，维持通用模块但标记回溯方向，或者在锁定状态下禁止拖入该资源。
