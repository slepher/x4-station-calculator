# Test Task List: StationDashboard UI Refactor

这些测试任务将对应于自动化测试脚本（如 `station-dashboard.spec.ts`）中的操作。

- [x] **Test Case 1: StationDashboard 基础渲染验证**
  - **描述**: 验证 `StationDashboard` 是否正确加载并显示默认状态。
  - **操作步骤**:
    - 打开空间站计划页面。
    - 检查是否存在 `StationDashboard` 容器。
    - 验证“材料视图”按钮是否处于激活状态。
    - 验证“时间视图”和“工人视图”按钮是否处于禁用状态。

- [x] **Test Case 2: 建设费用汇总逻辑验证**
  - **描述**: 验证总建设费用的计算和显示是否正确。
  - **操作步骤**:
    - 添加若干模块（如硅矿精炼厂）。
    - 检查“总建设费用”分组标题右侧的金额是否非零且符合预期。
    - 点击展开“总建设费用”分组。
    - 验证展开后的物料清单中是否包含了所有必需材料（如能量电池、加固金属板）。

- [x] **Test Case 3: 模块拆解分组验证**
  - **描述**: 验证单个模块的分组及其内部物料清单。
  - **操作步骤**:
    - 检查是否存在以“模块名 x 数量”命名的独立分组。
    - 验证该分组显示的金额是否正确。
    - 展开该模块分组，验证其内部显示的物料清单是否仅包含该模块所需的部分。

- [x] **Test Case 4: 价格倍率模拟联动验证**
  - **描述**: 验证底部 `PriceSlider` 调整后，仪表盘数值是否实时更新。
  - **操作步骤**:
    - 拖动底部的价格滑块（PriceSlider）。
    - 验证“总建设费用”分组和“模块”分组中的 Cr 数值是否随之变化。
    - 验证物料行中的单个 Cr 数值是否同步更新。

- [x] **Test Case 6: 模块合并与排序验证**
  - **描述**: 验证 `analyzeStation` 是否正确合并模块并按预定义顺序排列。
  - **操作步骤**:
    - 添加 1 个“硅矿精炼厂”。
    - 再添加 1 个同样的“硅矿精炼厂”。
    - 验证 `StationDashboard` 中是否只显示一个“硅矿精炼厂 x 2”分组。
    - 添加一个新模块（如“能量电池生产线”）。
    - 验证“硅矿精炼厂”分组是否保持在第一位（保持添加顺序）。

- [x] **Test Case 7: 材料 Tier 排序验证**
  - **描述**: 验证材料列表是否按 Tier 排序。
  - **操作步骤**:
    - 展开“总建设费用”或任意模块分组。
    - 检查材料顺序，验证 Tier 较低的材料（如能量电池）是否与 Tier 较高的材料（如加固金属板）按特定顺序排列（通常是升序或降序，需保持一致）。

- [x] **Test Case 8: i18n 完整性验证**
  - **描述**: 验证切换语言后，所有文案均正确翻译。
  - **操作步骤**:
    - 切换应用语言（如从中文切到英文）。
    - 验证视图切换按钮、分组标题、总计标题是否均已翻译，且没有显示 `ui.xxx` 原始键名。

- [x] **Test Case 9: UI 视觉一致性验证 (StationDashboard)**
  - **描述**: 验证字体、颜色和符号样式是否符合 `WareFlow` 规范。
  - **操作步骤**:
    - 检查主标题栏，验证标题在左侧，视图切换按钮在右侧。
    - 验证标题右侧没有 `[Cr]` 样式的按钮或文本。
    - 检查“总建设成本”标题，验证其为加粗的 `slate-300`。
    - 检查产线模块名称，验证其为中等字重、较淡的 `slate-200`。
    - 检查产线标题中的 `x` 符号，验证其透明度明显低于两侧文字。
    - 检查产线标题中的数量，验证其颜色和字重与模块名称完全一致。
    - 验证所有建设费用数值（Cr）是否统一呈现为红色 (`red-400`)。
    - 展开材料明细，验证材料价格是否为半透明红色 (`red-400/70`)。
