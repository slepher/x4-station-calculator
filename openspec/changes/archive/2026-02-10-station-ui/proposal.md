# Proposal: StationDashboard UI Refactor

## 1. 目标 (Goals)
本提议旨在重构空间站建设信息的展示界面。我们将创建一个全新的 `StationDashboard` 组件来替代现有的 `StationConstruction` 组件。

核心目标包括：
- **视觉一致性**: 将建设信息的 UI 风格完全对齐到资源流仪表盘 (`StationWareFlowsDashboard`)。
- **结构优化**: 采用多分组模式，将“总建设费用”与“各模块拆解”作为平级的折叠分组展示。
- **功能保留**: 完整保留现有的建设费用计算逻辑、价格倍率模拟以及材料清单拆分功能。
- **扩展性**: 为未来的“建设时间”和“工人统计”视图预留交互入口。

## 2. 核心变更 (Core Changes)

### 2.1 UI 结构重塑
- **多分组布局**: 
    - 第一个分组显示“总建设费用”，展开后显示空间站全局所需的材料汇总列表。
    - 后续每个模块（或同类模块组）作为一个独立分组，展开后显示该模块特有的材料需求。
- **组件复用**: 
    - 使用 `CollapsibleDetailList` 风格的分组头部。
    - 内部物料行采用 `StationWareFlow` 的视觉风格，但移除右侧的操作栏（收藏/锁定）。
- **仪表盘框架**: 
    - 顶部包含视图切换器（目前仅支持“材料视图”）。
    - 底部包含 `PriceSlider` 控件，用于实时调整建设成本。

### 2.2 逻辑整合与优化
- **核心逻辑迁移**: 新增 `analyzeStation` 函数到 `productionCalculator.ts`，作为建设信息的统一计算引擎。
- **数据结构增强**: 
    - **模块合并**: 自动合并相同类型的模块并累加数量。
    - **排序逻辑**: 模块列表严格遵循 `allIndustryModules` 的定义顺序；材料列表按 `tier`（等级）进行排序。
    - **直接价格计算**: 传入价格倍率参数，在计算层直接得出最终价格，减少 UI 层的计算压力。
- **i18n 支持**: 为所有 UI 字符串（包括视图切换器）添加多语言支持，确保无硬编码文案。

## 3. 预期影响 (Expected Impact)
- 提升用户界面的专业感，使其更符合《X4: 基石》的游戏 UI 风格。
- 增强信息的层级感，用户可以清晰地在“全局需求”和“局部模块需求”之间切换。
- 统一组件库，减少维护旧有非标准 UI 组件的成本。
