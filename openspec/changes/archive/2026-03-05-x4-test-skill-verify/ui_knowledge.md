# UI Knowledge: x4-test-skill-verify

## 适用范围

本文件用于说明 `x4-test-skill-verify` change 下文档格式契约的执行语义，不包含业务 UI 行为。

## 文档结构语义

- `test_tasks.md` 采用固定四章：1/2/3/4。
- 四章必须存在，允许空章。
- 章节主体采用任务树，不采用标题式测试项。

## 编号与层级语义

- 顶层任务：`- [ ] x.x <description>`
- 子任务：`  - [ ] x.x.x <description>`
- 第三级子项（可选）：`    - [ ] x.x.x.n <description>`
- 缩进层级固定：0 / 2 / 4 空格。
- 第三级子项若出现，`n` 必须在同父子任务下从 1 连续递增。

## Chapter 4 Bug 语义

- Bug 顶层格式：`- [ ] 4.x BUG-<number>: <description>`。
- `### BUG-...` 仅可作为历史文本，不可作为测试项主体。

## 一级任务末尾期望语义

- 所有一级任务（`x.x`）的最后一个子任务应为期望语义收敛点。
- 若最后子任务本身包含“期望”，可直接通过。
- 若最后子任务本身不包含“期望”，则其下所有第三级子项都必须包含“期望”。

## 具体值期望标注语义

- 具体值期望（数值或确定字符串）使用 `#期望: [...]`。
- 示例：
  - `再充延迟: 1 s #期望: ['1 s']`
  - `断言字段集合包含36项字段标签 #期望: [36]`
- UI 存在性/可见性类期望（如“按钮存在”“面板可见”）仅作为描述示例，规范仍统一使用 `#期望: [...]`。
- 示例：
  - `断言按钮可见 #期望: [true]`

## 写作与审查建议

1. 先写 `request/spec/design`，再落 `tasks/test_tasks/ui_knowledge`。
2. 若脚本处于 debug 阶段，本 change 允许先跳过脚本 gate。
3. 跳过 gate 时必须在文档中显式声明“临时策略”。
4. 脚本稳定后需要补做一次全量验证与格式回归。

## 快速检查清单

- 是否仅 4 章？
- 是否顶层全是 `[ ] x.x`？
- 是否子任务全是 `[ ] x.x.x` 且连续递增？
- 是否至少一个 `4.x BUG-` 顶层任务？
- 是否出现禁用格式（`步骤 n`、`### BUG-` 主体）？
