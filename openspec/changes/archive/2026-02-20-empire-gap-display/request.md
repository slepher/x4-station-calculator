# Request: 空间站显示帝国运营与帝国补给

## 功能描述

在空间站级别的 ContextToolbar 中添加"显示缺口"开关，开启后在空间站视图顶部显示帝国级的“帝国运营”和“帝国补给”，方便用户针对性地添加模块与调整优先级。

## 业务背景

用户在规划空间站时，需要了解帝国整体的资源缺口情况，以便决定在当前空间站生产哪些资源来填补缺口。目前需要切换到帝国总览才能看到缺口信息，操作不便。

## 用户场景

1. 用户在某个空间站规划产线
2. 开启"显示缺口"开关
3. 空间站视图顶部显示“帝国运营”和“帝国补给”
4. 用户点击缺口项的 + 按钮，直接添加对应的默认产线模块
5. 添加后，缺口数据实时更新

## 验收标准

### 开关功能
- [ ] ContextToolbar 第三组（技术与运营组）添加"显示缺口"开关
- [ ] 开关位于"站内补给"旁边
- [ ] 开关绑定到空间站的 `settings.showEmpireGaps` 字段
- [ ] 默认关闭

### 缺口显示
- [ ] 开启后，空间站视图顶部显示缺口分组
- [ ] 分组**仅在资源视图显示**，经济视图与体积视图不显示
- [ ] 显示顺序：帝国运营 → 帝国补给 → 产品 → 运营 → 补给 → 资源
- [ ] 帝国运营：来自 `empireGroupedFlows.empireGroups.operations`
- [ ] 帝国运营过滤：`netRate < 0` **或** 当前有效 `priority > 0` 的项
- [ ] priority 使用空间站内“修正后的优先级”计算结果（非原始覆盖值）
- [ ] 帝国运营分组直接使用 `empireStore` 的数据顺序，不在页面层额外排序
- [ ] 帝国补给：来自 `empireGroupedFlows.supply`，过滤规则为 `netRate < 0`，或 `netRate > 0` 且在当前站 `plannedModules` 中存在对应模块
- [ ] 如果某组过滤后为空，则不显示该组
- [ ] 缺口项支持展开明细（显示各空间站贡献）

### +/- 按钮功能
- [ ] 每个缺口项右侧显示 -/+ 按钮（- 在左，+ 在右）
- [ ] 点击 + 按钮直接添加该资源对应的默认产线模块
- [ ] 点击 - 按钮将对应模块数量 -1，减到 0 时移除该模块
- [ ] 当无可用默认产线模块时禁用 +
- [ ] 当缺口项 `netRate > 0` 时禁用 +
- [ ] 当不存在对应模块时禁用 -
- [ ] 添加/移除后缺口数据实时更新
- [ ] 缺口项不显示收藏按钮，该位置留空

### 数据同步
- [ ] 缺口数据与帝国总览保持一致（包括优先级过滤逻辑）
- [ ] 其他空间站更新时，缺口数据同步更新

## 技术约束

- 复用现有的 `EmpireWareFlow` 组件样式
- +/- 按钮行为与快速添加功能一致
- 开关状态持久化到 localStorage

## 依赖

- 依赖现有的 `empireGroupedFlows` computed 属性
- 依赖现有的快速添加模块逻辑
