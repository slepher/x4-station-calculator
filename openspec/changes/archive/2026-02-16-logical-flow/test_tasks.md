## 1. 单元测试 (Unit Tests)

对应文件：`tests/unit/logic-flow-backtrace.spec.ts`

### **1.1 findModuleForWare 种族回溯逻辑 (Race-Based Backtrace)**
- [x] **优先匹配指定种族 (Preferred Race)**
    - **步骤**：调用 `findModuleForWare`，传入 `wareId: 'energycells'`，`preferredRace: 'terran'`。
    - **预期**：返回模块的 `race` 应为 `terran`。
- [x] **Fallback 机制验证**
    - **步骤**：调用 `findModuleForWare`，传入 `wareId: 'advancedelectronics'`，`preferredRace: 'terran'`。
    - **预期**：由于该产物无 Terran 种族模块，应回退到 `race: 'default'` 的模块。

### **1.2 工业区特殊回溯 (Special Industrial Tracing)**
- [x] **Teladi 混合回溯验证**
    - **步骤**：
        1. 调用 `addGroup` 创建 `subCategory: 'teladi'` 的组。
        2. 调用 `expandUpstream` 添加 `wareId: 'scanningarrays'`。
    - **预期**：
        - 泰拉迪工业分类下，T3 产物回溯时，其 T1 前置依赖应正确识别为 `Teladianium` (race: teladi)。
        - 对于无泰拉迪变体的中间件，应正确回退到 `Default` 模块。

### **1.3 节点生命周期与清理 (Lifecycle & Cleanup)**
- [x] **节点降级与物理删除**
    - **步骤**：
        1. 添加 `antimattercells` 节点并设为 `manual`。
        2. 调用 `removeNode` 删除该节点。
    - **预期**：手动添加的节点在取消依赖后应降级为自动节点，或在不再被引用时彻底删除。
- [x] **级联清理 (Cascade Cleanup)**
    - **步骤**：
        1. 添加 `scanningarrays` 及其所有 `auto` 上游节点。
        2. 调用 `toggleLock` 锁定 `scanningarrays` 节点。
    - **预期**：锁定某个节点后，其所有不再被引用的上游自动节点应被自动清理。

### **1.4 逻辑修复与 Bug 校验 (Bug Fixes - Logical)**
- [x] **修复无名模块 (No Module Fix)**
    - **步骤**：调用 `expandUpstream` 添加一个无模块产物（如资源）。
    - **预期**：如果该产物不是基础资源且无模块，应跳过添加，而不是生成一个 `moduleId: undefined` 的空节点。
- [x] **武器组件回溯逻辑验证 (Bug 1 Logical)**
    - **步骤**：在 Store 中手动调用 `expandUpstream('weaponcomponents', race: 'default')`。
    - **预期**：生成的节点列表不应包含 `moduleId: undefined` 的节点。
- [x] **Teladi 种族回溯逻辑验证 (Bug 2 Logical)**
    - **步骤**：在 Store 中手动调用 `expandUpstream('missilecomponents', race: 'teladi')`。
    - **预期**：T1 阶段的产物必须是 `teladianium`。

### **1.5 智能排序插入算法验证 (Smart Insertion)**
- [ ] **智能排序插入算法验证 (Smart Insertion)**
    - **步骤**：
        1. 初始化一个组，包含 T3 (order: 0) 和 T1 (order: 0) 节点。
        2. 调用 `expandUpstream` 插入一个 T2 节点。
    - **预期**：
        - T2 节点被插入在索引 1 的位置。
        - 组内节点数组顺序为：[T3, T2, T1]。

- [x] **导航整合与视觉校验**

    - **预期**：

        - 产线组内不再显示独立的 SubCategory 标签。
        - Tier 列之间有明显的间距（48px），连线箭头清晰。
        - **能量电池始终位于 Tier 0 的最下方**（即使存在 EXT 资源节点）。
        - **Tier 0 节点不再显示锁定按钮**。
- [x] **候选区视觉通透性校验**

        - 顶栏与下方网格背景一致，无明显深浅分层或遮蔽感。
        - **文字不再呈现半透明灰色，而是清晰的白色/浅灰色**。

        - Tier 0 资源标签在中文下显示“资源”，英文下显示“RES”。

### **2.5 高级拖拽反馈验证 (Advanced Drag Feedback)**
对应文件：`tests/e2e/logic-flow-drag-feedback.spec.ts`

- [ ] **新产线幻影预览 (New Line Ghosting)**
    - **步骤**：拖拽模块悬停在“新建产线”区域。
    - **预期**：
        - 出现完整的产线组预览（Phantom Preview）。
        - 标题显示“Preview: [Module Name]”。
        - 预览中包含该模块所需的 T0 资源图标。
- [ ] **实时 T0 资源更新 (Real-time T0 Resource Header)**
    - **步骤**：拖拽模块悬停在现有产线组上。
    - **预期**：
        - 产线组标题栏实时显示该模块所需的 T0 资源。
        - 新增的资源图标应有脉冲动画 (`animate-pulse`)。
        - 现有资源数量如果增加，应有视觉反馈（可选）。
- [ ] **拖拽流向指引 (Dragged Object Flow)**
    - **步骤**：开始拖拽模块。
    - **预期**：
        - 鼠标跟随出现浮动预览组件。
        - 显示资源流向箭头（Inputs -> Target）。
        - **吸附 (Docking)**：当悬停在有效放置区（现有组或新建区）时，浮动组件应消失（opacity: 0）。
        - **分离 (Separation)**：当移出放置区时，浮动组件应重新出现。
- [ ] **最终状态验证 (Final State Verification)**
    - **场景 A (Add)**: 拖拽 -> 悬停现有组 -> 松开。
        - **预期**: 模块添加到该组，不创建新组。
    - **场景 B (Create)**: 拖拽 -> 悬停新建区 -> 松开。
        - **预期**: 创建且仅创建一个新组。
    - **场景 C (Cancel)**: 拖拽 -> 悬停现有组 -> 移出至空白处 -> 松开。
        - **预期**: **什么都不发生**。不添加模块，不创建新组。
    - **场景 D (Switch)**: 拖拽 -> 悬停现有组 -> 悬停新建区 -> 松开。
        - **预期**: **创建且仅创建一个新组**。现有组不受影响。
