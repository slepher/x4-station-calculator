## Context

当前的module-list-ui使用统一的蓝色标记来显示所有模块，这使得用户难以快速区分不同类型的模块。此外，自动生成的module-list缺乏明确的排序逻辑，导致用户查找特定模块时效率较低。我们需要改进这两个方面以提升用户体验。

## Goals / Non-Goals

**Goals:**
- 实现模块颜色编码系统，使不同类型的模块具有不同的颜色标记
- 实现模块列表的合理排序逻辑，提升用户查找效率
- 保持现有功能的向后兼容性
- 确保UI的一致性和美观性

**Non-Goals:**
- 重构整个module-list组件架构
- 添加除颜色和排序之外的新功能
- 修改模块的核心数据结构

## Decisions

1. **颜色编码方案**: 我们将使用Python脚本从游戏数据中提取颜色定义，并根据模块类型自动映射颜色，而不是使用统一的蓝色。具体实现如下：
   - 通过解析colors_final.xml文件获取游戏内置的颜色定义
   - 根据模块类型（production, storage, habitation, defense等）映射到相应的Holomap组件颜色
   - 使用预定义的类型到颜色映射表，例如：'production' -> 'holomap_component_production' -> 实际颜色
   - 对于未明确映射的类型，使用基础颜色作为默认值

2. **自动模块列表生成时排序逻辑**: 模块列表将按照以下优先级排序：
   - 按模块类型分组
   - 在同一类型内按模块层级(Tier)排序（高级产品在前）
   - 同一层级内按名称字母顺序排序
   - 确保相同类型的模块在列表中聚集显示
   - 在自动填充和补全算法中，也按Tier降序处理缺口和排序模块，确保高Tier模块优先处理
   - Tier计算方法：通过解析物品生产链深度确定，基础材料为Tier 0，高级产品随生产链深度增加而递增

3. **搜索列表排序逻辑**: 搜索列表将按照以下优先级排序：
   - 按模块分类的排序逻辑已有
   - 分类内部按照模块tier排序
   - 最终按字母顺序排序作为备选

4. **实现方式**: 
   - 创建排序函数来处理模块排序逻辑
   - 通过解析物品生产配方链来计算物品和模块的Tier层级

## Risks / Trade-offs

[Risk: 颜色过多导致视觉混乱] → Mitigation: 限制颜色种类数量，确保颜色搭配协调
[Risk: 排序逻辑复杂影响性能] → Mitigation: 优化排序算法，考虑缓存排序结果
[Risk: 现有用户不适应新颜色系统] → Mitigation: 提供过渡期的用户指导和帮助文档
