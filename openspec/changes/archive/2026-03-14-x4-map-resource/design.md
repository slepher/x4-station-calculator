# x4-map-resource 设计说明

## 设计目标
在不破坏现有 map 搜索交互的前提下，为 `MapWorkbenchView` 增加一套资源筛选工作台。
该工作台需要同时解决三个问题：
- 资源多选与每项独立最低丰度配置
- 日光特殊筛选与当前过滤可达约束
- 命中候选的稳定排序与快速聚焦
- 搜索命中和资源命中的高亮分层

## 1. UI 设计

### 1.1 资源入口与工作态侧栏
- 默认状态下，资源筛选组件以右上角“资源 + 过滤图标”按钮显示。
- 该按钮与左上搜索框同处地图顶部工具区，图标应使用人类直觉可识别的漏斗过滤形状。
- 按钮应挂载在地图壳层内部，使用与搜索框同类的覆盖定位方式；不要把它作为 `map-layout` 下的独立列块。
- 用户点击按钮后直接进入左右 split layout，而不是先在地图右上角展开一块资源浮层。
- 进入资源工作态后，父组件切换为左右 split layout：
  - 左侧地图自适应
  - 右侧资源栏固定宽度
- 默认态下不显示地图右上角资源区，只有入口按钮。
- 右侧资源栏保持当前面板宽度，不再作为覆盖层遮挡地图。
- 工作态右上角显示关闭按钮，关闭面板并退出 split layout。
- 面板结构分为三段：
  - 资源 tag 区：负责选择参与筛选的资源
  - 配置区：负责已选资源的最低丰度设置
  - 命中候选框：负责展示满足条件的 sector

### 1.2 配置区的层次
- 右上角资源 tag 与下方配置区采用分层文案策略：
  - 右上角资源 tag 使用短 i18n。
  - 下方配置区使用原有长 i18n。
- 每个已选资源单独渲染一行，左侧显示资源名或小 tag，右侧显示最低丰度下拉。
- 每行内容压缩在单行内，并按固定列对齐。
- 当已选普通资源数量大于等于 `2` 时，在配置区顶部增加 `所有项` 行。
- `所有项` 是批量操作入口，只对当前已选资源生效，不改变未选中资源的默认值。
- 不将下拉嵌入资源 tag 内部，避免 tag 宽度突变、换行不稳定和误触。
- `日光` 作为特殊 tag 排在资源 tag 最后，选中后在配置区显示百分比输入框，默认 `100%`。
- 资源 tag 顺序固定为：`ore -> silicon -> methane -> hydrogen -> helium -> ice -> rawscrap -> nividium -> sunlight`。
- 右上角资源 tag 的文案映射规则：
  - 普通资源使用 `res.*` 字典短名。
  - `sunlight` tag 复用 `res.energycells` 的短名，而不是显示 `日光 / Sunlight`。
- 下方配置区文案保持原有语义：
  - 普通资源继续显示游戏资源全称。
  - `sunlight` 配置项继续显示 `日光 / Sunlight` 及其百分比输入。

### 1.3 命中候选框
- 命中候选框位于配置区下方，在进入右侧过滤区后始终显示。
- 列表最多显示 `10` 个 sector。
- 当未选择任何 tag 时，候选列表进入默认预览模式：
  - 按 `ore + silicon + methane + hydrogen + helium` 的 `level` 总和降序排序
  - 取前 `10` 个 sector
- 每个候选项至少显示 sector 主名称；可附加总分或资源摘要，但不作为本次必需行为。
- 点击候选项后，复用现有搜索候选的聚焦与选中逻辑。

### 1.4 头部排布
- 右侧资源栏头部需要统一容纳资源 tag 区和关闭按钮。
- 不要依赖“仅在 selected 状态下追加右侧 padding”来避免遮挡。
- 更稳妥的方式是：
  - 将关闭按钮放进头部流式布局
  - 或对 tag 区在所有状态下一致预留关闭按钮空间

## 2. 数据与状态设计

### 2.1 资源配置状态
- 资源筛选状态建议使用按资源键控的结构：
  - 是否选中
  - 当前最低丰度
- 这样可以让每个资源独立维护门槛，并支持批量更新时只改写已选项。
- 面板展开/关闭状态与资源配置状态分离：
  - 关闭面板时只切换 UI 可见性
  - 不清空已选资源、最低丰度、日光输入等配置

### 2.1.1 关闭行为的状态拆分
- 资源过滤交互需要拆成两类状态：
  - 面板配置状态：已选资源、最低丰度、日光输入、候选排序所依赖的过滤条件
  - 地图表现状态：资源过滤产生的地图高亮集合
- 关闭面板时：
  - 保留面板配置状态，供当前页面会话内再次打开时恢复
  - 清理地图表现状态，避免面板关闭后地图仍残留资源命中高亮
- 该保留策略只覆盖当前页面会话，不要求刷新页面后从持久化存储恢复

### 2.2 丰度等级索引
- 基于 `regionyields.json` 为每个资源构建一份 `yield name -> rank` 的顺序索引。
- 比较最低丰度时，不直接比较字符串，而是比较 rank。
- 即便当前多个资源的等级名称集合一致，仍按“每个资源独立建立索引”实现，避免把数据结构假设写死。

### 2.3 当前过滤可达上限
- 对某个资源 `R` 计算“当前过滤可达上限”时：
  - 保留其它已选资源与日光条件
  - 暂时移除 `R` 自身的最低丰度约束
  - 在剩余候选中寻找 `R` 的最高 `yield`
- 该上限用于禁用下拉中不可达的选项，但不用于自动改写当前值。
- 如果当前值已经高于可达上限，UI 只展示警告，不做隐式修正。

### 2.4 sector 资源命中计算
- 命中判定使用 `maps.json` 中 sector 的 `resources[]`。
- 对每个已选资源执行：
  - sector 中必须存在该资源
  - sector 该资源的 `yield` rank 必须大于等于最低丰度 rank
- 只有全部已选资源都通过时，sector 才进入命中集合。
- 日光条件使用 `maps.json` 中 sector `area.sunlight`，并在运行时映射为百分比值，遵循 `1.0 = 100%`。

### 2.5 命中排序分数
- 候选排序分数定义为：当前已选资源在该 sector 中的 `level` 之和。
- 分数仅用于排序，不用于最低丰度判定。
- 同分时建议以显示名或 sector id 做稳定次序，避免列表跳动。
- 当只启用日光筛选时，候选按日光百分比排序。

## 3. 搜索与资源筛选并存设计

### 3.1 双通道结果集
- 搜索结果与资源筛选结果分别计算，不互相裁剪。
- 左上搜索继续负责：
  - 名称匹配
  - 搜索候选
  - 搜索聚焦
- 右上资源面板负责：
  - 资源条件配置
  - 资源候选列表
  - 资源命中高亮

### 3.2 渲染优先级
- 地图渲染层不要只维护单一 `highlightedSectorIds`。
- 建议拆成三类输入：
  - `selectedSectorId`
  - `searchHighlightedSectorIds`
  - `resourceHighlightedSectorIds`
- 样式优先级固定为：
  - 选中态
  - 搜索高亮
  - 资源高亮
- 当存在资源或日光筛选时，sector 内部填充不再使用种族色，而改为：
  - 命中项使用第一个已选筛选项颜色
  - 未命中项内部透明
- 当资源面板关闭时，应将 `resourceHighlightedSectorIds` 清空，但不要反向改写资源过滤配置本身。

### 3.3 交互一致性
- 资源候选点击应直接复用搜索候选的 focus 逻辑，避免产生两套不同的地图聚焦行为。
- 点击资源候选后，不清空资源筛选条件，也不自动修改搜索输入。
- 搜索清空只清理搜索态；资源清空只清理资源筛选态，两者互不越界。

## 4. 风险与对策

- 风险：右上面板内容增长后遮挡地图过多。
  - 对策：默认态只显示按钮；点击后直接切两列布局，避免在地图画面上叠加资源浮层；同时控制面板宽度、候选上限和配置区只渲染已选资源。
- 风险：同时存在搜索命中和资源命中时，用户难以理解高亮来源。
  - 对策：固定优先级，并在视觉上让资源高亮弱于搜索高亮。
- 风险：右上角 tag 与下方配置区采用两套名称体系，用户可能误以为文案不一致是 bug。
  - 对策：将差异限定为“上方便于扫描的短名”和“下方便于配置的长名”，并保持顺序、颜色与选中态一致。
- 风险：批量修改 `所有项` 时覆盖用户逐项配置，造成误判。
  - 对策：将 `所有项` 明确设计成一次性同步操作，且只在已选普通资源大于等于 `2` 个时出现。
- 风险：使用 `yield` 判门槛、使用 `level` 排序，逻辑来源不同易混淆。
  - 对策：在实现中明确拆分“通过条件”和“排序分数”两个计算阶段。
- 风险：用户不知道继续提高某个资源门槛是否还有候选。
  - 对策：对每个资源按“当前过滤可达”禁用不可达选项，并在当前值超出上限时给出警告。
- 风险：日光百分比与 `maps.json` 中小数值语义不一致。
  - 对策：统一在面板中展示百分比输入，并明确按 `1.0 = 100%` 做映射。
- 风险：关闭面板后若仍保留地图高亮，用户会误以为过滤仍在生效。
  - 对策：关闭动作显式清理资源高亮数据，但不清理面板配置状态。
- 风险：空选择时候选列表为空，用户无法理解打开过滤区后的默认用途。
  - 对策：提供默认前 `10` 条候选预览，并使用固定资源总分排序。
- 风险：关闭按钮只在部分状态下预留避让空间，导致未选择时遮挡 tag。
  - 对策：统一头部布局策略，不按“已选择/未选择”分叉处理按钮避让。
