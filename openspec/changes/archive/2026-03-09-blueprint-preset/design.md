## Context

蓝图系统同时承载两类来源：
1. 内置预设（空配/低配/中配/高配）；
2. 用户保存蓝图。

两类来源在 UI 选择、状态显示、保存目标上有不同语义。核心冲突发生在“当前已有活动蓝图时加载预设”：用户期望是“将预设应用到当前蓝图”，而不是“切换到新对象”。

## Goals

1. 明确区分“预设配装”和“蓝图配装”。
2. 统一蓝图状态名计算规则，消除“空配+红点”等歧义显示。
3. 在“活动已保存蓝图 + 载入预设”场景下，保持当前蓝图身份（id/name）不变。
4. `isDirty` 与红点仅由“实质变化”驱动，比较范围覆盖 C/U 槽。

## Non-Goals

1. 不重构 ship build 全局布局。
2. 不修改蓝图持久化版本结构。
3. 不引入新的蓝图实体类型字段（如额外 presetType 持久化字段）。

## Runtime Design

### 1) 列表分组与入口

- 入口：Fit 标题栏右侧按钮。
- 弹层：
  - 分组一：`预设配装`（built-in）
  - 分组二：`蓝图配装`（user）
  - 最大高度：`400px`

### 2) 预设加载双路径

#### 路径 A：普通路径（无活动已保存蓝图）
- 行为保持现状：载入预设后显示预设名，作为可编辑工作区内容。

#### 路径 B：应用到当前已保存蓝图（核心）
- 触发条件：
  - `activeBlueprintId` 有值；
  - 当前 `blueprint.id === activeBlueprintId`；
  - 当前蓝图非内置预设；
  - 当前 ship 与目标预设 ship 一致。
- 执行行为：
  - 用预设内容替换当前配装内容（连接与存储）。
  - 保留当前蓝图 `id/name`。
  - 保持 `activeBlueprintId` 指向当前蓝图。
  - 不进入“预设名显示模式”。

### 3) 状态名规则

- 若当前蓝图有 `name`：显示 `name`。
- 若无 `name` 且处于预设模式且未发生实质变化：显示预设名。
- 若无 `name` 且已发生实质变化：显示“自定义”。

### 4) Dirty 与红点规则

- `isDirty` 来源：当前 blueprint 快照与最后保存快照比较。
- 比较对象包含：
  - `connections`（装备/数量/护盾附属）
  - `storage`（deployables/countermeasure/drones/missiles）
- 红点展示条件：
  - `isDirty = true`
  - 且不属于“预设已载入但未变化”的免红点状态

## Risks

1. 若在应用预设时更新 `lastUpdated`，可能导致“无实质变化”误判 dirty。
2. 若错误保留预设模式标记，会导致状态名显示为预设名而非当前蓝图名。
3. 若漏比 `storage`，C/U 槽变更不会触发 dirty/红点。

## Validation

1. 单元：覆盖“活动蓝图+载入预设”的有变化/无变化两条路径。
2. 单元：覆盖删除当前蓝图、保存后 clean、已保存蓝图修改后 dirty。
3. UI：确认 Fit 标题栏分组名与弹层高度生效。
