# UI Knowledge: import-export

## 入口与交互路径

- 导出入口：TabBar 上现有导出按钮。
  - 点击后行为：打开导出弹窗（独立组件）。
  - 弹窗内容：模块统计列表（帝国/flow/ship）+ 导出文件名输入框。
  - 弹窗 footer：取消按钮、下载按钮（图标+文本）。
- 导入入口：TabBar 上现有导入按钮。
  - 点击后行为：先进入文件上传界面。
  - 上传成功后：进入导入配置面板。

## 导入配置面板信息结构

1. 模式选择
- 覆盖（overwrite）
- 增量（incremental）

2. 模块统计（来自上传 JSON）
- 帝国模块（`x4_empire_data`）及数据条数
- Flow 模块（`x4_logic_flow_plans`）及数据条数
- Ship 模块（`x4_ship_blueprints`）及数据条数

3. 模块级多选
- 用户可逐模块勾选是否参与本次导入。
- 覆盖模式默认全选当前 JSON 中可导入模块。
- 即使覆盖默认全选，用户仍可手动取消部分模块。

## 导入模式语义

- 覆盖模式
  - 语义：清理当前模块数据，写入导入结果。
  - 默认交互：模块多选默认全选。
  - active 行为：优先采用导入结果 `activeId`。
- 增量模式
  - 语义：在当前数据基础上追加。
  - 关键规则：所有导入对象 ID 重生并回填引用。
  - active 行为：仅在“当前 active 为空”或“active 对象为空且不脏”时切换。

## 关键可观察点

1. Empire
- active 切换时应联动 `activeStationId`。
- 生产页可见站点信息应同步切换。

2. Logic Flow
- 增量导入后方案条目增加。
- 若 active 未切换，当前方案面板保持不跳变。

3. Ship Build
- 增量导入后蓝图列表增加且 id 不冲突。
- active 切换时配装面板应展示新蓝图。

## 自动化断言建议

- 优先使用稳定 `data-testid` 做定位：
  - TabBar 导入按钮
  - TabBar 导出按钮
  - 导出弹窗容器
  - 导出文件名输入框
  - 导出下载按钮
  - 上传控件
  - 导入配置面板
  - 模块统计行
  - 模块勾选控件
  - 覆盖/增量切换控件
- 对于 active 相关断言，优先读取测试环境 store 暴露对象并与 UI 双重校验。
- 对增量导入断言增加“ID 去重 + 引用合法性”检查，避免仅验证数量。
- 对导出断言增加“默认文件名已预填 + 手动改名后下载名生效 + `.json` 自动补后缀”校验。

## 风险提醒

- 若覆盖模式默认全选未生效，可能出现“用户未导入预期模块”误解。
- 若模块统计与真实可导入条数口径不一致，用户可能做出错误勾选。
- 若 ID 重生漏掉嵌套引用，UI 可能表现为“导入成功但无法打开对象”。
