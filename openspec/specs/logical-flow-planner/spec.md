# Logical Flow Planner Specification

## Purpose
描述逻辑组网规划器的交互逻辑与功能需求，旨在提供一个可视化的产业链拓扑画布，支持拖拽式产线规划、节点隔离、血统管理等高级功能。

## Requirements

### Requirement: 逻辑组网画布布局 (Canvas Layout)
系统 SHALL 提供一个基于 Tier (0-3) 的纵向分列画布。
- **列分布**:
    - 第 1 列 (Tier 0): 基础资源（矿、气、冰、能）。
    - 第 2 列 (Tier 1): 基础材料加工。
    - 第 3 列 (Tier 2): 中级组件加工。
    - 第 4 列 (Tier 3): 终端产物加工。
- **自动对齐**: 节点拖入或生成后，必须自动吸附到其所属 Tier 的列中。

#### Scenario: 自动对齐与布局
- **前提**: 画布已清空
- **当** 用户从候选区拖入一个 Tier 3 的"高级卫星"
- **那么** 系统在第 4 列生成"高级卫星"产线面板
- **并且** 在第 1-3 列自动生成对应的上游依赖节点

### Requirement: 产线组管理 (Production Line Group Management)
系统 SHALL 允许用户将生产链组织为独立的"产线组"。
- **容器化**: 每个产线组是一个独立的布局容器，内部遵循 4 列布局。
- **自动命名**: 系统 SHALL 为新创建的产线组自动生成名称，格式为 `[一级分类] - [二级分类] - [组内 Tier 最高的第一个产物名]`。
- **排序**: 用户 SHALL 能够通过拖拽调整同一 Tier 列内产物节点的上下显示顺序。

#### Scenario: 自动命名产线组
- **前提**: 画布为空
- **当** 用户从"工业 - Terran"候选区拖入"计算机基板"到新建区
- **那么** 系统创建一个新产线组，默认名称为"工业 - Terran - 计算机基板"

### Requirement: 布局与视觉优化 (Layout & Visual Optimization)
系统 SHALL 对规划区与候选区进行布局优化，提升可观察性：
- **规划区 (Logic Flow Area)**:
    - **去中心化属性**: 规划区产线组 (Group) SHALL 移除"一级/二级菜单"属性显示。标题 SHALL 仅显示 **最高 Tier 的产物名称**。
    - **间距调整**: 同一产线组内，Tier 0-3 之间的列间距 SHALL 增大至 **48px (gap-12)**，以确保 SVG 连线箭头方向清晰可辨。
    - **能源排序**: 在 Tier 0 (资源列) 中，**能量电池 (Energy Cells)** SHALL 始终排列在 **最底端**，其优先级高于任何资源（包括 EXT 节点）。
    - **禁用锁定**: Tier 0 节点（资源/能量电池） SHALL **禁止锁定功能**，对应的 UI 锁定按钮 SHALL 隐藏。
- **候选区 (Candidate Zone)**:
    - **视觉通透**: SHALL 移除顶栏与网格区域的背景叠加 (`bg-slate-900/90`, `bg-slate-950/50`)，确保背景统一使用底层深蓝色 (`#0f172a`)。
    - **对比度增强**: 
        - 商品卡片文字 SHALL 使用纯白色 (`text-white`) 且加粗 (`font-bold`)，移除所有透明度设定。
        - 状态指示灯与图标 SHALL 提升亮度与尺寸 (指示灯 `w-1.5`, 图标 `opacity-80`)。
        - 商品卡片背景 SHALL 提升基础亮度 (`bg-white/5` 提升至 `bg-white/10` 级别)，消除灰蒙蒙的视觉感。
    - **搜索高亮**: 搜索匹配的商品 SHALL 仅进行高亮显示（使用蓝色边框），不执行列表过滤。
    - **能源排序**: 在 Tier 0 网格中，**能量电池** SHALL 始终排列在 **最底端**。
- **基础资源 (Tier 0)**:
    - 工业基础资源包含：能源电池、矿石、硅、各类气体。
    - **冰 (Ice)** 归属于农业分类，作为生产水的前置。
- **状态标识**: 已规划的产物标绿，未规划的标黄。

#### Scenario: 工业产线过滤
- **前提**: 选中"工业产线"一级分类
- **当** 用户点击"泰拉迪 (Teladi)"标签
- **那么** 候选区显示支持 `race: "teladi"` 的产物及其完整回溯链
- **并且** 泰拉迪分类下的 T3 产物列表 SHALL 包含 `race: "default"` 的所有 T3 产物。

### Requirement: 节点显示与视觉优化 (Node Display & Visual Optimization)
系统 SHALL 优化逻辑图节点的显示内容与连线视觉。
- **显示权重**: 
    - 生产节点 SHALL 以 **模块名称 (Module Name)** 为主要显示内容，彻底隐藏产物名称（Ware Name）。
    - 基础资源节点 (Tier 0) 由于无生产模块，SHALL 显示 **资源名称** 并标注 `RES`。
- **连线简化**: 
    - 系统 SHALL 自动隐藏指向 **能源电池 (Energy Cells)** 的连线，以防止复杂产业链下的视觉杂乱。
- **本地化**: 节点内所有名称均 SHALL 使用本地化 i18n 数据。

### Requirement: 节点来源视觉区分 (Node Provenance Visual Distinction)
规划区节点应根据其创建方式展示不同的视觉特征，以便用户区分"核心产物"与"系统补充"。

#### Scenario: Manual vs Auto visual check
- **前提**: 规划区包含一个手动添加的 `Hull Parts` 和一个自动生成的 `Graphene`
- **当** 用户观察这两个节点时
- **那么** `Hull Parts` 应显示为实线边框
- **并且** `Graphene` 应显示为虚线边框或带有轻微的 `Auto` 标识（i18n）

### Requirement: 产线转换与上游递归 (Module Transformation & Upstream Recursion)
系统 SHALL 将拖入的产物自动转换为对应的生产模块，并递归推演所有上游需求。
- **Teladi 回退**: 如果选定方法为 `teladi` 且无对应模块，则自动回退到 `default` 方法。
- **资源简化**: 矿物、气体、冰、能量电池统一显示为不可锁定的 Ware Node。

#### Scenario: Teladi 生产方式回退
- **前提**: 选中"工业-Teladi"分类
- **当** 用户拖入一个没有专用 Teladi 产线的产物
- **那么** 系统在该规划区生成该产物的"通用 (Default)"版生产模块

### Requirement: 紧凑视图与智能投放 (Compact View & Smart Drop)
系统 SHALL 在用户进行拖拽操作时，提供一个高效率的紧凑预览视图。
- **紧凑视图布局**:
    - **4 列网格**: 规划区在拖拽激活时 SHALL 切换为 `grid-cols-4` 布局，平铺展示所有现有的产线组卡片。
    - **容量适配**: 产线组卡片内部 SHALL 调整元素高度，使其在 4 列布局下依然能清晰展示最多 10 个节点的产业链（适配 5x2 的视觉密度预期）。
    - **T0 资源预览**: 标题栏同行排列 T0 资源预览，排除能量电池，遵循"依赖跟随排序"规则。
- **智能插入排序 (Tier-Based Insertion)**:
    - **智能定位**: 模块投放至已有产线组时，SHALL 不再简单追加至末尾。
    - **排序准则**: 系统 SHALL 根据模块的 Tier (Column) 自动定位插入点。高 Tier 靠前，低 Tier 靠后。
    - **同级后置**: 若组内已存在相同 Tier 的模块，新投放的模块 SHALL 插入在该 Tier 既有模块之后、更低 Tier 模块之前。

#### Scenario: 智能插入排序验证
- **前提**: 产线组 A 已包含 1 个 T3 节点和 1 个 T1 节点。
- **当** 用户将一个 T2 模块拖入产线组 A。
- **那么** T2 节点被插入在 T3 节点之后，T1 节点被自动后移至第 3 位。
- **并且** 整体视觉顺序保持 T3 -> T2 -> T1。

### Requirement: 新建产线占位符变换 (New Line Placeholder Transformation)
当用户将模块拖拽到"新建产线"区域时，该区域应展示为一条即将生成的产线的预览。

#### Scenario: Drag over new line zone
- **前提**: 规划区处于紧凑模式（正在拖拽中）
- **当** 拖拽一个模块（如"先进电子设备"）悬停在"+ 拖拽以创建"区域时
- **那么** 该区域应立即呈现为产线组样式
- **并且** 标题显示为"预览：先进电子设备"
- **并且** 内部网格显示一个蓝色虚线占位符，位于对应的 Tier 位置

### Requirement: 依赖跟随排序 (Dependency-Follow Sorting)
在产线组标题栏显示的资源列表，其排序必须严格跟随产线组内成品节点的顺序。

#### Scenario: Resources follow product order
- **前提**: 产线组内有成品 A（消耗硅）和成品 B（消耗矿）
- **当** 成品 A 排在成品 B 之前时
- **那么** 标题栏的资源列表应显示为 `[硅, 矿]`
- **当** 调整布局使成品 B 排在成品 A 之前时
- **那么** 标题栏的资源列表应更新为 `[矿, 硅]`
- **注意**: 若多个成品需要同一种资源，保留其首次出现的位置（去重）。

### Requirement: 候选区静态输入资源显示 (Static Input Resource Display in Candidate Zone)
在候选区的每一个产物卡片内部，直接展示该产线所需的 T0 输入资源。

#### Scenario: Static display
- **前提**: 候选区显示"先进电子设备"卡片
- **当** 用户查看该卡片时（无论是否拖拽）
- **那么** 在产物名称下方，应有一行小字显示其所需的 T0 资源
- **并且** 资源名称使用 i18n 短名，逗号分隔，字体较小且颜色较淡

### Requirement: 候选区衍生资源过滤 (Derived Candidate Resource Filtering)
候选区显示的产物列表（包括 T0 基础资源）必须完全基于生产链推导生成，严禁使用硬编码的组白名单或 Tier 判断。

#### Scenario: Dynamic T0 filtering by race
- **前提**: 候选区处于"工业"分类
- **当** 切换二级分类为"地球人 (Terran)"时
- **那么** 候选区仅显示地球人生产线所需的 T0 资源
- **并且** 自动隐藏不属于地球人产业链的资源
- **当** 切换二级分类为"默认 (Default)"时
- **那么** 候选区应显示标准产业链所需的全部资源（矿石、硅、气体等）

### Requirement: 锁定与虚化机制 (Locking & Ghosting)
系统 SHALL 允许用户锁定非基础资源的产线节点，以模拟外部供应。
- **行为**: 锁定后，该节点边框变为虚线（虚化），且其左侧所有 Tier 的前置依赖节点将从当前规划区移除。
- **Visual Status**: 锁定节点的存在不会触发候选区对应资源的"已规划"（绿色）状态。
- **Expansion Logic**: 
  - 当递归生成上游产线时，若遇到已锁定的同类资源节点，停止该分支的扩展。
  - 严禁修改已锁定节点的任何属性（如 `method`）。

#### Scenario: 锁定节点切断上游
- **前提**: 规划区已存在"船体零件"及其上游"精炼金属"
- **当** 用户点击"精炼金属"面板上的锁定按钮
- **那么** "精炼金属"面板变为虚线边框
- **并且** 该规划区内的"矿石"节点消失

### Requirement: Auto 节点"转正"操作
自动生成的虚线节点必须提供一个快速添加按钮，允许用户将其转换为手动管理节点。

#### Scenario: 点击添加按钮转正
- **WHEN** 用户点击虚线节点上的 ➕ 按钮
- **THEN** 该节点的状态应当从 `auto` 变更为 `manual`
- **AND** 连线应当从虚线变为实线

#### Scenario: Drag over auto node to promote
- **前提**: 产线组 A 中存在一个自动生成的 `Microchip` 节点（source: 'auto'）
- **当** 拖拽候选区的 `Microchip` 悬停在组 A 标题栏时
- **那么** 反馈标签应显示为 `Auto` (i18n)
- **当** 鼠标进一步悬停在组 A 的网格区域时
- **那么** 反馈标签应转变为 `Manual` (i18n)
- **并且** 在网格中 `Microchip` 的对应位置应显示预览停靠点
- **当** 用户松开鼠标（投放）时
- **那么** 现有的 `Microchip` 节点 `source` 变为 `manual`
- **并且** 节点边框从虚线变为实线

### Requirement: 基于 Module ID 的物理隔离
系统必须使用 `moduleId` 作为规划组内节点的唯一主键。即使产物相同，只要 `moduleId` 不同，它们也应当作为独立的节点存在。

#### Scenario: 不同体系的相同产物并存
- **WHEN** 用户在已有一个"通用船体部件"节点的组中，拖入一个"泰拉迪船体部件"
- **THEN** 系统应当在组内创建第二个独立的节点
- **AND** 两个节点分别显示其对应的模块名称

### Requirement: 血统元数据与递归回溯
每个手动添加的节点必须保存其来源体系（Lineage）。当系统为该节点自动生成上游产线时，必须优先使用父节点的 `lineage` 作为 `findModuleForWare` 的 `race` 参数。

#### Scenario: 自动继承父节点血统
- **WHEN** 一个带有 `industrial_terran` 血统的节点产生上游需求
- **THEN** 自动生成的上游节点也应当默认使用 `industrial_terran` 模块
- **AND** 即使存在通用的同类产物模块，也应当优先匹配泰拉迪/特兰体系的模块

### Requirement: T0 资源强制合并
所有 Tier 0 资源（如矿石、能量电池等）不具备血统属性，在规划组内必须始终合并为同一个资源节点。

#### Scenario: 跨体系 T0 资源合并
- **WHEN** 泰拉迪产线和通用产线都需要"能量电池"
- **THEN** 规划组内只应当出现一个"能量电池"节点
- **AND** 该节点的总需求量应为各方需求之和

### Requirement: iOS 风格锁定滑块
候选区和规划组 Header 必须包含一个 iOS 风格的滑块（Toggle Switch），用于控制体系锁定状态。

#### Scenario: 候选区滑块 UI 表现
- **WHEN** 渲染候选区菜单栏
- **THEN** 系统应当显示一个滑块
- **AND** 滑块旁应当显示当前选定的血统名称（如 `Terran-Agri`）

### Requirement: 锁定状态下的强行同化与拦截
当规划组处于"锁定"状态时，任何尝试进入该组的资源必须强制重映射为锁定血统对应的 `moduleId`。如果该血统不支持该资源，则必须禁止进入。

#### Scenario: 锁定状态下的拖拽拦截
- **WHEN** 用户尝试将一个"特兰"模块拖入一个锁定位"泰拉迪"体系的规划组
- **THEN** 系统应当显示禁止符号 🚫
- **AND** 禁止将该模块放入该组

### Requirement: 切换锁定权限检查
仅当规划组内所有手动添加的模块血统一致时，系统才允许切换锁定状态。

#### Scenario: 血统冲突时禁用滑块
- **WHEN** 规划组内同时存在手动添加的"泰拉迪"和"通用"模块
- **THEN** Header 上的锁定滑块应当处于禁用（Disabled/Gray）状态
- **AND** 提示用户存在血统冲突
